# 验证码刷新参数

登录工作流的 `captcha` 步骤只负责识别并填入 4 位验证码，不提交登录。刷新验证码必须用低痕迹坐标点击（和普通 `click` 相同的 `_low_profile_click`），不能用 Playwright 的 `locator.click` / `page.click`。点得太快会让瑞数网关返回 HTTP 400。

## 参数

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `retry` | `5` | 识别失败或结果不是 4 位时，换一张图再认，直到次数用完，然后转人工输入 |
| `refresh_before` | `0` | 第一次识别之前先换几张图。`0` 表示不预刷新。旧字段名 `pre_refresh` 仍然有效 |
| `refresh_interval_ms` | `800`–`1500` 随机 | 每次点击验证码图片之前等待的毫秒数，会再抖动约 ±10%。写得比 800 更小也会被抬到 800。旧字段名 `pre_refresh_interval_ms` 仍然有效 |

## 示例

不预刷新（默认，推荐先这样跑）：

```yaml
- action: captcha
  captcha_img: "img[src^='data:image']"
  captcha_input: "#validateOnly_verifyCode"
  retry: 5
```

识别率差、需要先换图时，两次点击至少隔 0.8 秒：

```yaml
- action: captcha
  captcha_img: "img[src^='data:image']"
  captcha_input: "#validateOnly_verifyCode"
  retry: 5
  refresh_before: 2
  refresh_interval_ms: 1200
```

`refresh_before: 2` 会在识别前用低痕迹点击验证码图片 2 次，每次先等约 1.2 秒（再加一点抖动），等图片地址变化后再截图识别。识别结果为空或不是 4 位时，同样用这条路径换图，直到 `retry` 用完。

不要把间隔改到 800 毫秒以下，也不要在 YAML 里写原生点击。请求一旦出现 HTTP 400，这一步会暂停，不再继续刷新。
