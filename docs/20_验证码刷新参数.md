# 验证码刷新参数

登录工作流的 `captcha` 步骤只负责识别并填入 4 位验证码，不提交登录。刷新验证码必须用低痕迹坐标点击（和普通 `click` 相同的 `_low_profile_click`），不能用 Playwright 的 `locator.click` / `page.click`。点得太快会让瑞数网关返回 HTTP 400。

## 参数

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `self_check_rounds` | `3` | 识别结果不合格后，刷新两次再识别，这算一轮。没写、写空或不是正整数时都是 3。旧字段 `retry` 在没写本字段时仍当作轮数，不会报错 |
| `retry` | 同 `self_check_rounds` | 旧配置。没有 `self_check_rounds` 时当作自检轮数，并在日志里说明。两者都写时以 `self_check_rounds` 为准 |
| `refresh_before` | `0` | 第一次识别之前先换几张图。`0` 表示不预刷新。旧字段名 `pre_refresh` 仍然有效 |
| `refresh_interval_ms` | `800`–`1500` 随机 | 每次点击验证码图片之前等待的毫秒数，会再抖动约 ±10%。写得比 800 更小也会被抬到 800。旧字段名 `pre_refresh_interval_ms` 仍然有效 |

## 示例

不预刷新（默认，推荐先这样跑）：

```yaml
- action: captcha
  captcha_img: "img[src^='data:image']"
  captcha_input: "#validateOnly_verifyCode"
```

识别率差、需要先换图时，两次点击至少隔 0.8 秒：

```yaml
- action: captcha
  captcha_img: "img[src^='data:image']"
  captcha_input: "#validateOnly_verifyCode"
  refresh_before: 2
  refresh_interval_ms: 1200
  self_check_rounds: 3
```

`refresh_before: 2` 会在识别前用低痕迹点击验证码图片 2 次，每次先等约 1.2 秒（再加一点抖动），等图片地址变化后再截图识别。识别结果去掉空白后如果不是严格的 4 位数字或英文字母，就再点图片两次，等第二次的新图稳定后再识别。这个刷新再识别的过程重复 `self_check_rounds` 轮，默认 3 轮。现场旧配置如果只写了 `retry: 5`，这 5 就是轮数，不会因为不认识这个字段而中断。都不合格时暂停，等人工输入。

每次点击之前至少等 0.8 秒。预刷新和后面的自检刷新用的是同一次等待，不会连着点。图片地址没变时，最多再隔 0.8 秒看 4 次，然后停止，不会用很短的间隔反复读页面。刷新只点验证码图片，不重新请求图片地址，也不刷新整个页面。

不要把间隔改到 800 毫秒以下，也不要在 YAML 里写原生点击。请求一旦出现 HTTP 400，这一步会暂停，不再继续刷新。
