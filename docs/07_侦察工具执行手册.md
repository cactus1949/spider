# 07 侦察工具执行手册（从零开始）

> **目标读者**：第一次接手本项目、需要在现场跑 `recon` 工具采集数据的工程师。

> **兼容性**：核心环境为 Windows（生产/现场），同时给出 macOS/Linux（开发/调试）的等价命令。

## 第一部分：开发环境搭建

### 1.1 安装 Python 3.11+

⚠️ **必须 3.11 或更高版本**（`pyproject.toml` 中 `requires-python = ">=3.11"`）。

#### Windows
1. 访问 <https://www.python.org/downloads/windows/>，下载 **Python 3.11.x** 安装包（建议 3.11，最稳）。
2. 双击安装时，**务必勾选** `Add python.exe to PATH`（否则后面所有命令都用不了）。
3. 验证：

   ```bat
   python --version
   pip --version
   ```

   应输出 `Python 3.11.x`。

#### macOS
```bash
# 推荐用 pyenv 或官方包
brew install python@3.11
python3.11 --version
```

### 1.2 安装 Git

- Windows：<https://git-scm.com/download/win> 默认下一步即可。
- macOS：`xcode-select --install` 或 `brew install git`。

### 1.3 克隆项目

```bash
git clone <仓库地址> spider-gd
cd spider-gd
```

### 1.4 创建并激活虚拟环境

⚠️ **强烈建议用虚拟环境**，避免依赖污染系统 Python。

#### Windows（PowerShell）
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

> 若 PowerShell 报"无法加载，因为在此系统上禁止运行脚本"：以管理员身份运行
> `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`，然后重新激活。

#### Windows（cmd）
```bat
python -m venv .venv
.venv\Scripts\activate.bat
```

#### macOS / Linux
```bash
python3.11 -m venv .venv
source .venv/bin/activate
```

激活成功后命令行前会出现 `(.venv)` 前缀。

### 1.5 安装项目依赖

项目依赖在 `pyproject.toml` 中分组：核心依赖（自动安装）、`dev`（开发测试）、`ocr`（验证码识别）、`win`（Windows 平台）、`online`（联网附加能力）。

⚠️ **首次安装升级 pip**：

```bash
python -m pip install --upgrade pip
```

#### 开发机（macOS / Linux）
```bash
pip install -e ".[dev,ocr]"
```

#### Windows 现场机
```bat
pip install -e ".[dev,ocr,win]"
```

> `win` 组包含 `WMI` 和 `pywin32`，仅在 Windows 上可装；macOS/Linux 装会失败但不影响（依赖里已有 `sys_platform == 'win32'` 守卫）。
> `online` 组（FastAPI/uvicorn/dingtalk-stream）只在跑 Mock 网站或网关服务时需要——侦察工具本身不依赖。

### 1.6 安装 Playwright 浏览器

侦察工具的浏览器侦察阶段依赖 Chromium：

```bash
# 1) Playwright Python 库已随 pip install 装好；这里下载浏览器二进制
playwright install chromium
```

成功后浏览器位于：

- Windows：`%LOCALAPPDATA%\ms-playwright\chromium-XXXX\`
- macOS：`~/Library/Caches/ms-playwright/chromium-XXXX/`
- Linux：`~/.cache/ms-playwright/chromium-XXXX/`

### 1.7 安装 PyInstaller（仅打包机器需要）

```bash
pip install pyinstaller
```

> 现场运行 `recon.exe` 的机器**不需要**装 PyInstaller。

### 1.8 验证开发环境

依次执行，全部通过才说明环境就绪：

```bash
# 1) 主程序可启动
python -m spider_gd --help

# 2) 单元测试全部通过（约 100+ 用例，秒级）
python -m pytest tests/unit/ -x

# 3) 侦察工具自检
python tools/recon_tool/cli.py doctor
```

`doctor` 子命令会检查 Playwright Chromium 是否就绪、当前用户是否有管理员权限（macOS/Linux 上权限项可忽略）。

## 第三部分：侦察工具打包（PyInstaller）

> 打包目标：在不装 Python 的纯净 Windows 机器上，双击 `recon.exe` 即可运行。

### 3.1 打包前置条件

- 当前 venv 已 `pip install -e ".[dev,ocr,win]"`
- 已 `playwright install chromium`
- 已 `pip install pyinstaller`
- 当前目录在仓库根（`spider-gd/`）

### 3.2 方式一：一键脚本（仅 Windows，推荐）

```bat
tools\build_recon.bat
```

脚本三步走：
1. `pyinstaller tools\recon.spec --noconfirm` —— 生成 `dist\recon\` 目录及 `recon.exe`
2. `playwright install chromium` —— 确保打包机本地有 Chromium
3. 把 `%LOCALAPPDATA%\ms-playwright\*` 拷贝到 `dist\recon\playwright-browsers\`

完成后产物结构：

```
dist/recon/
├── recon.exe                    # 主入口
├── _internal/                   # PyInstaller onedir 运行时
├── playwright-browsers/         # Chromium（约 200MB）
│   └── chromium-XXXX/
└── run_recon.bat                # 现场运行入口（需手动从 tools/ 拷过来）
```

⚠️ `tools\run_recon.bat` 不在 spec 的 datas 里，**打包后需手动复制**到 `dist\recon\` 下：

```bat
copy tools\run_recon.bat dist\recon\
```

### 3.3 方式二：手动分步（macOS/Linux 调试，或 Windows 排错）

```bash
# 1) 仅打 PyInstaller（onedir 模式）
pyinstaller tools/recon.spec --noconfirm

# 2) 确保浏览器就绪
playwright install chromium

# 3) 把 Chromium 拷到产物目录（让现场机不联网也能跑）
#    Windows
xcopy /E /I /Y "%LOCALAPPDATA%\ms-playwright" "dist\recon\playwright-browsers"
#    macOS
cp -R ~/Library/Caches/ms-playwright dist/recon/playwright-browsers
#    Linux
cp -R ~/.cache/ms-playwright dist/recon/playwright-browsers

# 4) 复制运行脚本
cp tools/run_recon.bat dist/recon/    # macOS/Linux
copy tools\run_recon.bat dist\recon\  # Windows
```

### 3.4 打包要点

| 项目 | 说明 |
| --- | --- |
| `--onedir` | spec 已选 onedir（EXE+COLLECT），**不要改成 onefile**——onefile 启动慢且 Chromium 解压会失败 |
| `pathex` | 已包含 `tools/` 与 `src/`，因为 `recon_tool` 会 import `spider_gd` |
| `hiddenimports` | 已显式列入 `recon_tool.*` 与 `spider_gd.infrastructure.network.*`，PyInstaller 静态扫描可能漏掉这些动态 import |
| `PLAYWRIGHT_BROWSERS_PATH` | `run_recon.bat` 自动 set 为 `%~dp0playwright-browsers`，让 Playwright 用本地副本 |
| 体积预估 | onedir 总体积约 **300~400MB**（Python 运行时 ~80MB + Chromium ~200MB + 依赖 ~50MB） |

### 3.5 打包常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `ModuleNotFoundError: spider_gd` | `pip install -e .` 没执行，或 venv 没激活 |
| 跑 exe 时 `Executable doesn't exist at .../chromium` | `playwright-browsers/` 目录没拷或 `PLAYWRIGHT_BROWSERS_PATH` 没生效 |
| exe 启动后立刻闪退 | 双击在 PowerShell 里跑 `.\recon.exe doctor`，看真实报错 |
| `WMI` import 报错 | spec 里没加，在 `hiddenimports` 追加 `wmi`、`win32com.client` |
| 杀软误报 | PyInstaller 打的 exe 常被杀软标黑，向客户报备/加白；或改用 Portable Python 方案（参考 `06_现场侦察工具.md` §7） |

## 第四部分：运行侦察工具（用 Mock 网站联调）

### 4.1 联调前提

确保两个进程同时在跑：

1. **Mock 站**：`http://localhost:8000` 已启动（第二部分）
2. **侦察工具**：从仓库根目录或 `dist/recon/` 启动

### 4.2 开发模式（直接 Python 运行）

⚠️ `recon_tool` 包**没有** `__main__.py`，所以**不能**用 `python -m recon_tool`。请直接执行 `cli.py`：

```bash
# 仓库根目录执行
python tools/recon_tool/cli.py start --url http://localhost:8000
```

或先把 `tools/` 加入 PYTHONPATH，再用模块路径调用：

```bash
# macOS/Linux
PYTHONPATH=tools python -m recon_tool.cli start --url http://localhost:8000

# Windows (PowerShell)
$env:PYTHONPATH="tools"; python -m recon_tool.cli start --url http://localhost:8000
```

### 4.3 打包后模式（exe）

```bat
cd dist\recon

REM 方式 A：双击 run_recon.bat（默认目标 https://pm.gd.csg.cn/，需要先改）
run_recon.bat

REM 方式 B：直接调 exe，指定 mock 站
recon.exe start --url http://localhost:8000
```

> 联调 Mock 站时，建议把 `run_recon.bat` 中的 `TARGET_URL` 临时改为 `http://localhost:8000`。

### 4.4 子命令速查

| 子命令 | 用途 | 联调示例 |
| --- | --- | --- |
| `start` | **完整侦察**：baseline → U-Key 等待 → 网络 → 浏览器 → 报告 → 打包 | `recon.exe start --url http://localhost:8000` |
| `network` | 仅网络侦察（路由/适配器/DNS/连通性） | `recon.exe network` |
| `browser` | 仅浏览器侦察（HAR + 页面快照） | `recon.exe browser --url http://localhost:8000` |
| `report <dir>` | 对已有会话目录重新生成 `summary_report.md` | `recon.exe report recon_20260622_140000` |
| `pack <dir>` | 对已有会话目录重新打包 zip | `recon.exe pack recon_20260622_140000` |
| `doctor` | 自检 Playwright/权限/路径 | `recon.exe doctor` |

⚠️ `start` 流程会在两步处**等待回车**：
1. 第 1 步采集 baseline 路由表前——确认 U-Key **未插入**；
2. 第 2 步采集 after 路由表前——提示**插入 U-Key**。

联调 Mock 时 U-Key 不存在，**直接连按两次回车**即可跳过。

### 4.5 产出物结构

每次 `start` 在当前工作目录下生成 `recon_YYYYMMDD_HHMMSS/`：

```
recon_20260622_140000/
├── network/
│   ├── route_before.json        # baseline 路由表
│   ├── route_after.json         # U-Key 插入后路由表
│   ├── route_diff.json          # 路由差异
│   ├── wifi_info.json
│   ├── gateway_dns.json
│   ├── connectivity.json        # 到目标 443 端口的连通性
│   ├── adapters.json
│   └── system_info.json
├── browser/
│   ├── session.har              # 全量 HAR（含响应体，最关键）
│   ├── pages/
│   │   ├── 01_<url-slug>.html
│   │   ├── 01_<url-slug>.png
│   │   └── ...
│   ├── cookies.json
│   ├── localstorage.json
│   ├── sessionstorage.json
│   └── downloaded_files/        # 浏览器中点导出下载下来的文件
├── analysis/
│   ├── api_endpoints.json       # 自动提取的 API 列表（按 method+path 去重）
│   └── auth_info.json           # bearer_tokens / cookies / 特殊 URL 参数
├── summary_report.md            # 人可读侦察报告（首要阅读对象）
└── recon_20260622_140000.zip    # 整个目录的 zip 副本
```

### 4.6 验证侦察结果正确性（用 Mock 站验证）

侦察一遍 Mock 站后，检查以下项：

- [ ] `network/connectivity.json` 中目标端口（80）可达
- [ ] `browser/session.har` 文件 > 100KB（含响应体）
- [ ] `browser/pages/` 至少 2 个 HTML（登录页 + daily_overview）
- [ ] `browser/cookies.json` 包含 `VShPPFZUwMakO`（Mock 站的 SessionMiddleware Cookie）和 `X-Auth-Token`
- [ ] `analysis/api_endpoints.json` 包含 `POST /api/export`
- [ ] `analysis/auth_info.json` 的 `special_params` 中出现 `HdKGccbL`
- [ ] `browser/downloaded_files/` 有点击导出按钮下载的 `.xlsx`
- [ ] `summary_report.md` 渲染后 API 表格非空

只要以上 8 项都过，说明工具链路完整、可上现场。

## 第五部分：现场实战 SOP（Checklist）

> 打印贴在电脑上，按顺序执行。从 `06_现场侦察工具.md` §9 提炼。

### 5.1 出发前（办公室）

- [ ] `recon.exe doctor` 通过
- [ ] `dist/recon/` 整包拷到现场笔记本（含 `playwright-browsers/`）
- [ ] U 盘 / 网盘留好回传通道
- [ ] 笔记本电池满电、电源线随身
- [ ] **关闭杀软实时扫描**（避免拦截 PyInstaller exe）

### 5.2 现场操作

- [ ] **以管理员身份**打开 PowerShell（路由表读取需要）
- [ ] `cd` 进入 `dist\recon\`
- [ ] 启动：`recon.exe start --url https://pm.gd.csg.cn/`（或双击 `run_recon.bat`）
- [ ] 第 1 步提示出现 → **确认 U-Key 未插入** → 回车（采集 baseline）
- [ ] 第 2 步提示出现 → **请客户插入 U-Key** → 等网卡识别（看到任务栏 WiFi 图标变化） → 回车
- [ ] 网络侦察自动完成（约 30 秒），看到 `[OK] 连通性` 才继续
- [ ] 浏览器自动打开 → **手动登录**（用户名+密码+验证码）
- [ ] 登录后**依次浏览每一类数据页面，每页都点一次"导出"**：
  - [ ] 日清算
  - [ ] 日前出清结果
  - [ ] 实时出清结果
  - [ ] 月度结算
  - [ ] （客户额外要求的页面）
- [ ] 全部完成后**关闭浏览器窗口**（CLI 会捕获到关闭事件，进入分析阶段）
- [ ] 等待"分析"+"打包"提示完成（约 1 分钟）
- [ ] 确认目录下出现 `recon_<timestamp>.zip`
- [ ] **拔出 U-Key**
- [ ] zip 拷贝到 U 盘 / 网盘 / 邮件

### 5.3 回办公室

- [ ] 解压 zip，先**通读 `summary_report.md`**
- [ ] `session.har` 拷到 `tests/fixtures/`（注意脱敏 Token）
- [ ] `api_endpoints.json` 交给开发同事配置 `api_fetcher`
- [ ] 在办公室用 `page.route_from_har()` 验证可离线回放

## 第六部分：故障排查 FAQ

### 6.1 Chromium 启动失败

| 报错关键字 | 处理 |
| --- | --- |
| `Executable doesn't exist at .../chromium-XXXX/...` | `playwright-browsers/` 没拷或路径错。设 `PLAYWRIGHT_BROWSERS_PATH` 指向正确目录，或重新 `playwright install chromium` |
| `BrowserType.launch: Target page, context or browser has been closed` | Chromium 被杀软拦截。临时关闭杀软或加白 |
| `Permission denied` 启动 Chromium | macOS/Linux 上 `chmod +x` 整个 `playwright-browsers/chromium-XXXX/chrome-linux/chrome` |

### 6.2 网络权限不足

- 现象：`Get-NetRoute` 返回空、`adapters.json` 缺关键字段
- 原因：未以管理员身份运行
- 处理：右键 PowerShell → "以管理员身份运行"，重跑

### 6.3 验证码识别失败

- 现象：`ddddocr` 识别率低或 import 报错
- 处理：
  - 确认装了 `ocr` 组：`pip install -e ".[ocr]"`
  - 引导模式下**人工输入验证码**（侦察工具本就支持手动登录）
  - 验证码识别不属于侦察工具核心路径，识别失败不影响 HAR 录制

### 6.4 Excel 导出为空 / 不出现

- 现象：浏览了导出页但 `downloaded_files/` 为空
- 处理：
  - 确认 Playwright context 启用了 `accept_downloads=True`（代码已默认开启）
  - 检查 `session.har` 中是否有 `/api/export` 类请求——HAR 里有但本地没文件，说明前端通过 `Blob` 触发下载未走 download 事件，从 HAR 中按 `bodySize > 0` 的二进制响应反查 base64 即可
  - Mock 站联调：直接点页面"导出"按钮触发标准 `Content-Disposition: attachment` 下载

### 6.5 PowerShell 执行策略阻止脚本

- 现象：`.\Activate.ps1` 或 `setup_routes.ps1` 报"无法加载，因为在此系统上禁止运行脚本"
- 处理（管理员 PowerShell）：

  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
  ```

  或单次绕过：

  ```powershell
  PowerShell -ExecutionPolicy Bypass -File .\setup_routes.ps1
  ```

### 6.6 `pip install` 卡死或超时

- 现场专网通常无法访问公网 PyPI——**不要在现场装依赖**。
- 所有依赖必须在办公室装好、打成 PyInstaller exe 带过去。
- 万一现场临时要装，使用内网镜像：

  ```bash
  pip install -i https://pypi.tuna.tsinghua.edu.cn/simple <pkg>
  ```

### 6.7 单元测试失败

- 优先看错误是真的代码问题还是环境问题
- `pytest_asyncio` 报错：确认 `pytest-asyncio>=0.23` 已装，`pyproject.toml` 中 `asyncio_mode = "auto"`
- `import spider_gd` 失败：确认在仓库根、venv 已激活、`pip install -e .` 已执行

### 6.8 `python -m recon_tool` 报错 `No module named recon_tool.__main__`

- 这是预期行为：`recon_tool` 没有 `__main__.py`
- 用 `python tools/recon_tool/cli.py <subcmd>` 或 `python -m recon_tool.cli <subcmd>`（需把 `tools/` 加到 PYTHONPATH）
