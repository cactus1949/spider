# 06 现场侦察工具

> **一句话定位**：带一台 Windows 电脑+这把工具到客户现场，把 U-Key 一插，剩下的事情交给它——录制完整网络环境、HAR 网络流量、页面 HTML、截图、Cookie/Token，让后续所有开发与调试都能在办公室离线进行，**现场跑一次，数据够用一辈子**。

---

## 1. 概述与使用场景

### 1.1 为什么需要这个工具

电力交易平台（pm.gd.csg.cn）只能通过客户专网访问，专网入口是一把 **USB U-Key（无线随身 WiFi）**。每去一次客户现场，意味着：

- 需要协调客户时间（U-Key 不能带走）；
- 现场环境受限（不一定能装开发工具、不一定能联调）；
- 数据采集机会有限（一次现场约 30~60 分钟）。

所以，**每一次现场都必须把后续 1~3 个月开发可能用到的数据全部采回来**。这就需要一个"全自动、傻瓜式、不漏采"的侦察工具。

### 1.2 使用场景故事

```
[09:00] 工程师到达客户现场，打开笔记本电脑
[09:02] 双击 recon.exe，工具进入待机状态
        终端提示："请插入 U-Key 以开始网络侦察..."
[09:03] 客户把 U-Key 插入电脑
        工具立刻：
          - 抓取 U-Key 插入"前/后"路由表差异
          - 抓取 WiFi 信号、网关、DNS
          - 测试到 pm.gd.csg.cn 的连通性
          - 30 秒后完成网络侦察
[09:04] 工具自动启动 Chromium 浏览器，开始 HAR 全量录制
        终端提示："请在浏览器中完成登录..."
[09:05] 工程师手动登录（密码+验证码），随后浏览：
          - 日清算页面 → 点击导出
          - 日前出清结果 → 点击导出
          - 实时出清结果 → 点击导出
          - 月度结算 → 点击导出
        每一个页面的 HTML、截图、所有 API 请求/响应都被静默录制
[09:25] 浏览完毕，工程师按 Ctrl+Q
        工具自动：
          - 解析 HAR，提取所有 API 端点
          - 提取 Cookie/Token/LocalStorage
          - 生成人可读侦察报告 summary_report.md
          - 打包为 recon_20260619_090000.zip（约 50~200MB）
[09:27] 拔出 U-Key，带着 zip 离开现场
[09:30] 回到办公室，把 zip 解压交给开发同事
        从此再也不需要联网真平台开发——HAR 可离线回放，HTML 可离线分析
```

## 2. 工具形态

### 2.1 打包形式

- **首选**：PyInstaller 单文件 exe（`recon.exe`），现场零依赖；
- **次选**：Portable Python（绿色版 Python + 项目代码），适合 Playwright + Chromium 包体太大（~200MB+）的场景；
- **运行权限**：需要管理员权限（读取路由表、网络适配器需要）。

## 3. 阶段一：网络侦察（U-Key 插入时自动触发）

### 3.1 触发时机

工具启动后进入"等待 U-Key 插入"状态，通过 `infrastructure/network/usb_monitor.py` 监听 USB 事件：

```python
from infrastructure.network.usb_monitor import wait_for_usb_insertion

# 阻塞等待 U-Key 插入
print("[等待] 请插入 U-Key...")
new_adapters = wait_for_usb_insertion(timeout=300)  # 最多等 5 分钟
print(f"[检测] 新增网络适配器：{new_adapters}")
```

### 3.2 采集项清单

所有命令在 PowerShell 子进程中执行，结果序列化为 JSON。

| 项目 | 命令 / 方法 | 产出文件 |
|------|-----------|---------|
| 路由表（U-Key 插入前） | `Get-NetRoute \| ConvertTo-Json` | `route_before.json` |
| 路由表（U-Key 插入后） | `Get-NetRoute \| ConvertTo-Json` | `route_after.json` |
| 路由差异分析 | Python diff 两份 JSON | `route_diff.json` |
| WiFi 连接信息 | `Get-NetConnectionProfile \| ConvertTo-Json` | `wifi_info.json` |
| WiFi 信号强度 | `netsh wlan show interfaces` | `wifi_signal.json` |
| WiFi 网关/DNS | `Get-NetIPConfiguration` + `Get-DnsClientServerAddress` | `gateway_dns.json` |
| DNS 解析 | `nslookup pm.gd.csg.cn <wifi_dns>` | `dns_resolve.json` |
| 连通性测试 | `Test-NetConnection pm.gd.csg.cn -Port 443` | `connectivity.json` |
| 全部网络适配器 | `Get-NetAdapter \| ConvertTo-Json` | `adapters.json` |
| 系统信息 | Python `platform`、`sys`、`os.environ` | `system_info.json` |

### 3.3 实现要点

- 路由表"前/后"对比时，必须**在 U-Key 插入前先抓一份基线**，这是工具一启动就要做的事；
- DNS 解析必须**指定 WiFi 适配器的 DNS** 而不是系统默认 DNS（专网 DNS 与公网 DNS 可能解析结果完全不同）；
- 所有 PowerShell 调用都加超时（10 秒），避免某条命令卡住整个流程；
- 复用 `infrastructure/network/diagnoser.py` 已实现的诊断函数，不要在侦察工具里重写。

### 3.4 产出

```
recon_{timestamp}/network/
├── route_before.json
├── route_after.json
├── route_diff.json
├── wifi_info.json
├── wifi_signal.json
├── gateway_dns.json
```

## 4. 阶段二：浏览器侦察（核心，最有价值）

### 4.1 启动方式

网络侦察通过后（连通性测试 OK），**自动启动 Playwright Chromium**，进入 HAR 全量录制模式。

```python
from playwright.async_api import async_playwright

async with async_playwright() as p:
    browser = await p.chromium.launch(headless=False)  # 必须可见，用户要交互
    context = await browser.new_context(
        record_har_path="output/browser/session.har",
        record_har_content="attach",       # 包含响应体
        record_har_mode="full",            # 全量
        viewport={"width": 1440, "height": 900},
        accept_downloads=True,
    )
    # 同时启动 Tracing（可选，更详细）
    await context.tracing.start(screenshots=True, snapshots=True, sources=True)
    page = await context.new_page()
    await page.goto("https://pm.gd.csg.cn/")
    # ... 进入用户操作循环 ...
```

### 4.2 录制能力一览

#### 4.2.1 HAR 全量录制（最关键）

- **覆盖范围**：每一个 HTTP/HTTPS 请求的 URL、Method、请求头、请求体、响应头、**响应体**、状态码、Timing；
- **包含二进制响应**：导出 Excel 的响应体也会以 base64 形式保存在 HAR 内；
- **离线回放**：

```python
# 后续开发时
context = await browser.new_context()
await context.route_from_har("recon_data/session.har", not_found="fallback")
# 现在所有发往 pm.gd.csg.cn 的请求都会从 HAR 直接返回响应
```

#### 4.2.2 页面 HTML 快照

监听 `page.on("framenavigated", ...)`，每次 URL 变化时自动保存：

```python
page_index = 0

async def on_navigated(frame):
    global page_index
    if frame == page.main_frame:
        page_index += 1
        # 等待网络空闲，确保 Vue 渲染完成
        try:
            await page.wait_for_load_state("networkidle", timeout=5000)
        except:
            pass
        html = await page.content()
        url_slug = sanitize_filename(page.url)
        path = f"output/browser/pages/{page_index:02d}_{url_slug}.html"
        Path(path).write_text(html, encoding="utf-8")
        # 同时截图
        await page.screenshot(path=path.replace(".html", ".png"), full_page=True)

page.on("framenavigated", lambda f: asyncio.create_task(on_navigated(f)))
```

## 5. 阶段三：分析与打包

### 5.1 自动分析 HAR

解析 `session.har`，做以下事情：

#### 5.1.1 API 端点提取与分类

```python
import json
from urllib.parse import urlparse
from collections import defaultdict

def analyze_har(har_path: Path) -> dict:
    har = json.loads(har_path.read_text(encoding="utf-8"))
    entries = har["log"]["entries"]

    api_list = []
    for entry in entries:
        req = entry["request"]
        res = entry["response"]
        url = req["url"]
        path = urlparse(url).path
        ctype = next((h["value"] for h in res["headers"]
                      if h["name"].lower() == "content-type"), "")

        # 分类
        if any(x in ctype for x in ["javascript", "css", "image", "font"]):
            category = "static"
        elif "html" in ctype:
            category = "page"
        elif any(x in ctype for x in ["spreadsheet", "excel", "octet-stream", "csv"]):
            category = "export"      # ← 导出类，最有价值
        elif "json" in ctype:
            category = "data"
        else:
            category = "other"

        api_list.append({
            "method": req["method"],
            "url": url,
            "path": path,
            "status": res["status"],
            "content_type": ctype,
            "category": category,
            "size": res.get("bodySize", 0),
            "duration_ms": entry.get("time", 0),
        })

    # 去重（同 method+path 合并）
    dedup = defaultdict(list)
    for api in api_list:
        dedup[(api["method"], api["path"])].append(api)

    return {"raw": api_list, "deduped": dict(dedup)}
```

#### 5.1.2 认证信息提取

扫描 HAR 找出所有 `Authorization` Header、`Cookie` Header、特殊 URL 参数（如平台特有的 `HdKGccbL`）：

```python
def extract_auth(har_path: Path) -> dict:
    har = json.loads(har_path.read_text(encoding="utf-8"))
    auth_info = {
        "bearer_tokens": set(),
        "cookies": {},
        "special_params": defaultdict(set),
    }
    for entry in har["log"]["entries"]:
        for h in entry["request"]["headers"]:
            if h["name"].lower() == "authorization":
                auth_info["bearer_tokens"].add(h["value"])
            elif h["name"].lower() == "cookie":
                for kv in h["value"].split(";"):
                    if "=" in kv:
                        k, v = kv.strip().split("=", 1)
                        auth_info["cookies"][k] = v
        # 检查 URL 参数中的可疑认证字段
        url = entry["request"]["url"]
        for suspect in ["HdKGccbL", "token", "sign", "_t"]:
            if suspect in url:
                from urllib.parse import urlparse, parse_qs
                qs = parse_qs(urlparse(url).query)
                if suspect in qs:
                    auth_info["special_params"][suspect].update(qs[suspect])
    # 转 set 为 list 以便 JSON 序列化
    auth_info["bearer_tokens"] = list(auth_info["bearer_tokens"])
    auth_info["special_params"] = {k: list(v) for k, v in auth_info["special_params"].items()}
    return auth_info
```

## 6. HAR 文件的后续利用价值

HAR 是这个工具最有价值的产出，后续开发中至少有 3 类用法：

### 6.1 离线 Mock 开发（开发同事不再依赖现场）

```python
# tools/dev_offline.py
from playwright.async_api import async_playwright

async def offline_dev():
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        context = await browser.new_context()
        # 让所有发往 pm.gd.csg.cn 的请求都从 HAR 取响应
        await context.route_from_har(
            "recon_data/session.har",
            url="**/pm.gd.csg.cn/**",
            not_found="fallback"
        )
        page = await context.new_page()
        await page.goto("https://pm.gd.csg.cn/login")
        # 现在登录、点导出、收 Excel 全都从 HAR 出，办公室也能跑
```

### 6.2 API 自动发现

```python
# tools/discover_apis.py
import json
from pathlib import Path

def discover():
    har = json.loads(Path("recon_data/session.har").read_text(encoding="utf-8"))
    for entry in har["log"]["entries"]:
        url = entry["request"]["url"]
        if "export" in url.lower() or "download" in url.lower():
            print(f"发现导出 API: {entry['request']['method']} {url}")
            print(f"  请求体: {entry['request'].get('postData', {}).get('text', '')[:200]}")
            print(f"  响应大小: {entry['response'].get('bodySize', 0)} 字节")
```

### 6.3 测试数据来源

HAR 里的响应体 = 真实数据样本 = 单元测试 fixture：

```python
# tests/conftest.py
import json, base64
from pathlib import Path

def load_har_response(path_pattern: str) -> bytes:
    """从 HAR 中按 URL pattern 取响应体作为测试 fixture"""
    har = json.loads(Path("tests/fixtures/session.har").read_text(encoding="utf-8"))
    for entry in har["log"]["entries"]:
        if path_pattern in entry["request"]["url"]:
            content = entry["response"]["content"]
            if content.get("encoding") == "base64":
                return base64.b64decode(content["text"])
            return content["text"].encode("utf-8")
    raise FileNotFoundError(path_pattern)

def test_parse_daily_settlement_excel():
    # 不需要连真平台，HAR 里就有真实 Excel
    excel_bytes = load_har_response("exportItemsWithoutCalVersion")
    result = parse_daily_settlement(excel_bytes)
    assert len(result) > 0
```

## 7. 技术实现要点

| 项目 | 要点 |
|---|---|
| Playwright 浏览器 | 打包前必须执行 `playwright install chromium`，PyInstaller 通过 `--add-data` 把 `~/.cache/ms-playwright/chromium-*/` 一并打包，约 200MB |
| PyInstaller | 用 `--onedir` 而不是 `--onefile`（onefile 启动慢且解压临时目录会失败 chromium 启动）；最终交付一个文件夹+exe |
| 替代方案 | 如打包困难，改用 **Portable Python**：把 Python 解释器+venv+项目代码打成 zip，现场解压跑 `run.bat`，体积差不多但调试方便 |
| 管理员权限 | 在 manifest 中声明 `requireAdministrator`，否则路由表读取部分项目会失败 |
| 时间预算 | 现场全流程 20~30 分钟（网络 30 秒、浏览器录制 15~20 分钟、分析打包 1 分钟） |
| HAR 体积 | `record_har_content="attach"` 会把响应体以 base64 内嵌，HAR 可能 100~500MB；如太大可改用 `omit` 但会失去 Mock 价值 |
| 杀毒软件 | 客户机器可能有杀软，PyInstaller exe 容易被误报，建议同时提供 portable 方案 |

## 8. 与其他模块的关系

```
                    [现场侦察工具 tools/recon_tool/]
                              │
              ┌───────────────┼─────────────────┐
              ▼               ▼                 ▼
       infrastructure/   产出 session.har   产出 api_endpoints.json
       network/          ──────────────►   ────────────────────►
       (复用 diagnoser、  链路1 离线开发      api_fetcher 配置依据
        usb_monitor)     与单元测试 fixture
```

- **网络侦察部分**：直接复用 `infrastructure/network/diagnoser.py` 与 `infrastructure/network/usb_monitor.py`，**不要重写**；
- **HAR 产出**：作为链路 1（爬虫核心）开发与测试的**默认输入**，办公室离线开发时通过 `route_from_har` 加载；
- **api_endpoints.json**：作为 `api_fetcher` 模块的**配置雏形**，开发同事据此填充实际请求构造；
- **strategy_suggestion.md**：作为 PM 与开发同事的**决策依据**，决定哪些数据走 API、哪些走 RPA；
- **位置**：`tools/recon_tool/` 独立目录，与主项目代码隔离，单独打包发布。

## 9. 现场操作 SOP（标准操作流程）

> 工程师把这一节打印出来贴在电脑上，按步骤做就好。

```
[准备]
  [ ] U-Key 在客户处（不可带走）
  [ ] 笔记本电脑装好 recon.exe + 浏览器（Chromium 已打包）
  [ ] 以管理员身份打开 PowerShell

[现场]
  [1] 双击 recon.exe（或 PowerShell 里跑 .\recon.exe start）
  [2] 工具进入"等待 U-Key"状态，先抓基线路由
  [3] 客户插入 U-Key
  [4] 工具自动完成网络侦察（约 30 秒）
      → 看到"网络侦察完成 ✓"再继续
  [5] 工具自动打开浏览器，跳转到 https://pm.gd.csg.cn/
  [6] 在浏览器中手动登录（用户名+密码+验证码）
  [7] 登录后依次浏览每一个数据页面，每个页面点一次"导出"：
      [ ] 日清算
      [ ] 日前出清结果
      [ ] 实时出清结果
      [ ] 月度结算
      [ ] （其他客户要求的页面）
  [8] 浏览完毕，按 Ctrl+Q 结束录制
  [9] 工具自动分析 + 打包（约 1 分钟）
  [10] 确认目录下出现 recon_<timestamp>.zip
  [11] 拔出 U-Key
  [12] 把 zip 拷贝到 U 盘 / 云盘 / 邮件，带回办公室

[办公室]
  [13] 解压 zip，先打开 summary_report.md 通读一遍
  [14] 把 session.har 与 fixtures 提交到 tests/fixtures/（注意脱敏 Token）
  [15] 把 api_endpoints.json 交给开发同事配置 api_fetcher
  [16] 完成
```

工具开发完成后，按以下清单验收：

- [ ] `recon.exe doctor` 通过（Chromium 就绪、管理员权限就绪）
- [ ] 在测试机上空跑 `recon.exe network`，能正确抓取 10 项网络信息
- [ ] 模拟插拔 U 盘，能触发"插入"事件并执行路由对比
- [ ] `recon.exe browser` 启动后，浏览任意网站能产出 HAR + HTML + 截图
- [ ] HAR 中的 Excel 响应体能用 `route_from_har` 离线回放成功
- [ ] `recon.exe report` 能从已有 HAR 生成 summary_report.md
- [ ] 整个 zip 包大小可控（< 500MB），可通过邮件/网盘传输
- [ ] 在没装 Python 的纯净 Windows 上，双击 exe 可直接运行
