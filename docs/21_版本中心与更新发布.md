# 版本中心与更新发布（稳定版 / 测试版）

> 文档编号：21
> 关键词：版本记录、history.json、自动更新、beta 渠道、离线

## 1. 版本记录存在哪里？

**它不在客户端里，也不是数据库，就是发布服务器上的一个静态 JSON 文件。**
设置 → 版本中心打开时，Electron 主进程会请求 `history.json`：

| 渠道 | 读取地址 | 服务器文件位置（相对发布根目录） |
| --- | --- | --- |
| 正式版 | `http://47.101.175.39:20152/releases/history.json` | `releases/history.json` |
| 测试版 | `http://47.101.175.39:20152/releases/beta/history.json` | `releases/beta/history.json` |

- 地址由 `src/spider_gd/release-channels.json` 的 `updateUrl` 决定，客户端只读本渠道的地址。
- 没有这个文件时版本中心会显示「当前渠道的版本记录尚未发布，请联系维护人员提供安装包」。
- 安装包文件名不能由 `history.json` 指定：客户端固定按
  `产品名-版本-setup.exe` 在**同目录**下拼接下载地址（测试版产品名是 `广东电力数据采集－测试版`）。
- 自动更新（electron-updater）用的是同目录的 `latest.yml`（正式版）/ `beta.yml`（测试版），
  和 `history.json` 是两套东西：前者决定"有没有新版本"，后者只用于版本中心的历史列表。

### history.json 格式（schemaVersion 1）

```json
{
  "schemaVersion": 1,
  "channel": "beta",
  "releases": [
    {
      "version": "0.2.8-beta.2",
      "publishedAt": "2026-11-20",
      "notes": ["版本中心离线提示更友好。", "自动更新离线时不再空转。"]
    },
    {
      "version": "0.2.8-beta.1",
      "publishedAt": "2026-11-20",
      "notes": []
    }
  ]
}
```

约束（客户端会校验，不合法直接报"版本记录格式不正确"）：

- `channel` 必须与文件所在渠道一致；`releases` ≤ 200 条，版本不能重复；
- 正式版版本号 `x.y.z`；测试版 `x.y.z-beta.N`，N 为正整数；
- `publishedAt` 必须是 `YYYY-MM-DD` 且是真实日期；
- `notes` ≤ 100 条，每条 ≤ 4000 字；除 `version/publishedAt/notes` 外不允许其它字段
  （禁止在 JSON 里塞 URL/文件名，避免客户端下载任意地址）。

## 2. 发布目录结构

以 `REMOTE_PATH=/home/developer01/dljy/spider-gd/upload/releases` 为例（nginx 把
`/releases` 映射到这个目录）：

```
upload/releases/
├── latest.yml                                  正式版自动更新元数据
├── history.json                                正式版版本记录
├── 广东电力数据采集-0.2.8-setup.exe
├── 广东电力数据采集-0.2.8-setup.exe.blockmap
└── beta/
    ├── beta.yml                                测试版自动更新元数据（不是 latest.yml）
    ├── history.json                            测试版版本记录
    ├── 广东电力数据采集－测试版-0.2.8-beta.2-setup.exe
    └── 广东电力数据采集－测试版-0.2.8-beta.2-setup.exe.blockmap
```

- **测试版就放在正式版同一个目录的 `beta/` 子目录**，不需要另开服务器，也不用改 nginx
  （只要 `/releases` 映射在，`beta/` 自动可访问）。
- 上传后可以用这些命令确认：
  ```bash
  curl -I http://47.101.175.39:20152/releases/latest.yml
  curl -I http://47.101.175.39:20152/releases/history.json
  curl -I http://47.101.175.39:20152/releases/beta/beta.yml
  curl -I http://47.101.175.39:20152/releases/beta/history.json
  ```

## 3. 发布流程

1. 维护 `release-history.json`（仓库根目录）：
   这是**版本记录的唯一数据源**，按渠道列出要展示的版本、发布日期、更新说明。
2. 打包：
   ```bash
   bash release.sh              # 正式版
   bash release.sh beta 2       # 测试版 0.2.8-beta.2
   ```
   `release.sh` 会编译后端/前端、调用 `tools/build_release_history.py` 生成
   `frontend/dist/history.json`，然后 scp 到服务器对应目录（正式版根目录 / 测试版 `beta/`）。
3. 只生成、不上传（例如手工用 FinalShell 传文件）：
   ```bash
   SKIP_UPLOAD=1 bash release.sh beta 2
   python tools/build_release_history.py --channel beta --out frontend/dist/history.json
   ```
4. 发版后把新版本追加进 `release-history.json` 并提交，保证记录可追溯。

> `release.sh` 的 SSH 端口默认 22（`SSH_PORT` 可改）。此前脚本里用的 `20152` 是 nginx 的
> HTTP 端口，不是 SSH 端口；如果现场是通过跳板/FinalShell 上传，用 `SKIP_UPLOAD=1` 只产包即可。

## 4. 离线使用说明

现场机器常年离线，本功能遵循"联网能力只是锦上添花"：

- **离线不影响采集、任务调度、浏览器接管、数据落盘**。
- 版本中心：只在打开面板时联网读取；断网/超时会提示
  「当前无法联网获取版本记录；离线不影响本地采集，联网后请点刷新版本记录」。
- 自动更新：启动后 5 秒、以及每 4 小时的**自动检查在离线时直接跳过**（不再发起必然失败的请求）；
  用户手动点"检查更新"仍会尝试，插上外网后即可生效。
- 版本中心只展示**当前渠道**的历史版本，下载会用默认浏览器打开安装包地址，不会自动安装或回滚；
  重装旧版前请先备份数据。
- 升级/安装仍然依赖发布服务器可达；离线现场升级需要人工拷贝安装包。

## 5. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 版本中心报"尚未发布" | 服务器缺 `history.json` | 按第 2、3 节生成并上传 |
| 报"版本记录格式或渠道不正确" | JSON 渠道/字段不合规 | `python tools/build_release_history.py --channel <渠道>` 重新生成 |
| 报"响应地址与当前渠道不一致" | nginx 把请求重定向到别的地址 | 检查 nginx 的 `alias/root` 与 `/releases`、`/releases/beta/` 映射 |
| 下载 404 | 安装包不在 `history.json` 同目录/文件名不符 | 对比 `产品名-版本-setup.exe` 命名 |
| beta 自动更新 404 | `beta.yml` 没放到 `releases/beta/` | 上传 `beta.yml`（不是 `latest.yml`） |
