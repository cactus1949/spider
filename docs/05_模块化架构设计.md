## 1. 架构设计原则

本系统采用 **"分层 + 协议 + 可插拔"** 的设计哲学，以应对多种异构部署场景（单机/双机/离线）。

| 原则 | 说明 | 落地手段 |
|------|------|---------|
| **Protocol 驱动** | 模块间不直接依赖具体实现，而是依赖 `typing.Protocol` 定义的接口契约。 | `interfaces/` 目录集中存放所有 Protocol；调用方仅 import Protocol。 |
| **部署模式无关** | `core/` 业务逻辑代码不感知运行在单机还是双机模式下。 | 通过 `main.py` 在启动时按 `deploy_mode` 注入不同实现。 |
| **通信层可插拔** | 同一接口可由"本地直调 / HTTP API / 消息队列"三种实现满足。 | 工厂方法 `create_xxx(mode)` 返回对应的实现实例。 |
| **故障隔离** | 一个模块（如钉钉机器人）崩溃不能影响爬虫主流程。 | 全局异常捕获 + 优雅降级 + 进程级隔离（NSSM 服务）。 |
| **配置驱动** | 启动哪些模块、连接哪些后端，全部由 `.env` / `config/settings.py` 决定，不改代码。 | `pydantic-settings` 读取环境变量，按 `deploy_mode` 启停模块。 |

### 1.1 设计理念图

```
        ┌──────────────────────────────────────┐
        │   Protocol 接口契约 (interfaces/)     │  ← 稳定不变
        └──────────────────────────────────────┘
                  ↑              ↑
    实现 A（本地） │              │ 实现 B（HTTP/远程）
                  │              │
        ┌─────────┴─────┐  ┌─────┴────────┐
        │  core/        │  │  gateway/    │     ← 可替换
        │  infrastructure/│ │              │
        └───────────────┘  └──────────────┘
                  ↑
        ┌─────────┴──────────┐
        │   main.py (DI入口)  │   ← 按 deploy_mode 装配
        └────────────────────┘
```

## 3. Protocol 接口定义

所有 Protocol 集中在 `interfaces/` 目录，**业务模块只能依赖 Protocol，不能跨层互相 import**。

### 3.1 爬虫接口

```python
# interfaces/crawler_protocol.py
from typing import Protocol, Optional
from dataclasses import dataclass


@dataclass
class CrawlTask:
    """爬虫任务输入"""
    task_id: str
    date: str          # YYYYMMDD
    data_type: str     # 数据类型，如 "daily_settlement" / "spot_price"
    priority: int = 0  # 优先级：0 普通，1 高，2 紧急


@dataclass
class CrawlResult:
    """爬虫任务输出"""
    task_id: str
    success: bool
    data: Optional[bytes]              # Excel/JSON 二进制数据
    record_count: int                  # 采集到的记录数
    error_msg: Optional[str] = None
    duration_ms: int = 0               # 耗时（毫秒）


class ICrawler(Protocol):
    """爬虫模块统一接口"""

    async def login(self) -> bool:
        """登录平台，返回是否成功"""
        ...

    async def fetch_data(self, task: CrawlTask) -> CrawlResult:
        """根据任务采集数据"""
        ...

    async def get_session_status(self) -> dict:
        """获取当前会话状态（Token 是否有效、剩余时间等）"""
        ...

    async def refresh_token(self) -> bool:
        """刷新 Token，避免重新登录"""
        ...
```

### 3.2 存储接口（拆分为状态追踪 + 文件落地）

遵循 **SQLite 与 Excel 职责分离原则**：SQLite 仅用于任务状态追踪，实际数据以 Excel/台账 文件形式落地。为此将原 `IStorage` 拆为两个独立接口。

```python
# interfaces/storage_protocol.py
from typing import Protocol, Optional
from dataclasses import dataclass


@dataclass
class TaskRecord:
    task_id: str
    name: str
    status: str           # pending/running/completed/failed
    output_dir: str
    created_at: str
    finished_at: Optional[str] = None


@dataclass
class TaskItemRecord:
    task_id: str
    indicator_name: str
    target_date: str
    status: str           # pending/success/failed/skipped
    file_path: Optional[str] = None
    file_size: int = 0
    error_msg: Optional[str] = None


class ITaskStateStore(Protocol):
    """任务状态追踪（SQLite）"""
    async def create_task(self, task: TaskRecord) -> str: ...
    async def update_task_status(self, task_id: str, status: str) -> None: ...
    async def create_item(self, item: TaskItemRecord) -> None: ...
    async def update_item_status(self, task_id: str, indicator: str, status: str, **kwargs) -> None: ...
    async def get_pending_items(self, task_id: str) -> list[TaskItemRecord]: ...
    async def get_task_summary(self, task_id: str) -> dict: ...


class ILocalLanding(Protocol):
    """本地文件落地管理"""
    def create_task_dir(self, task_name: str, exec_time: str) -> str:
        """创建任务目录结构，返回根路径"""
        ...

    def save_data_file(self, task_dir: str, indicator: str, date: str, data: bytes) -> str:
        """保存数据文件，返回文件路径"""
        ...

    def generate_ledger(self, task_dir: str, task_id: str) -> str:
        """从 SQLite 生成台账 Excel，返回文件路径"""
        ...

    def compress_task(self, task_dir: str) -> str:
        """压缩任务目录为 zip，返回 zip 路径"""
        ...
```

### 3.3 网关接口（拆分为告警网关 + Agent 适配）

原 `IGateway` 拆分为两个职责独立的接口，避免单向推送与双向控制逻辑耦合：

- `IAlertGateway`：**单向推送**（钉钉/飞书/邮件 Webhook），错误报警。
- `IAgentAdapter`：**双向交互控制**（可拆卸），接收远程指令并返回结果。

```python
# interfaces/alert_protocol.py
from typing import Protocol


class IAlertGateway(Protocol):
    """告警网关接口 — 单向推送通知"""
    async def send_alert(self, level: str, message: str, event_type: str = "info") -> bool:
        """发送告警到配置的通道"""
        ...

    def is_in_silence_window(self) -> bool:
        """当前是否在静默时段"""
        ...
```

```python
# interfaces/agent_protocol.py
from typing import Protocol
from dataclasses import dataclass


@dataclass
class AgentCommand:
    raw_text: str           # 原始指令文本
    action: str             # 解析后的操作类型
    params: dict            # 参数
    permission_level: str   # 需要的权限级别: readonly/config/system


@dataclass
class AgentResponse:
    success: bool
    message: str
    attachments: list[str] = None  # 文件路径列表


class IAgentAdapter(Protocol):
    """远程Agent接口 — 双向交互控制（可拆卸）"""
    async def handle_command(self, command: AgentCommand) -> AgentResponse:
        """处理来自Agent的指令"""
        ...

    async def send_response(self, response: AgentResponse) -> bool:
        """发送结果回Agent"""
        ...
```

## 4. 部署模式配置设计

### 4.1 五种部署模式速览

| 模式 | 启动模块 | 禁用模块 | 适用场景 |
|------|---------|---------|---------|
| `standalone_wired` (A) | core + infrastructure + alert + agent + web_ui | 无 | 单机 + 有线网络 + U-Key |
| `standalone_wireless` (B) | core + infrastructure + alert + agent + web_ui | 无（仅网卡名不同） | 单机 + USB WiFi / 4G 模块 |
| `dual_machine_crawler` (C) | core + infrastructure + web_ui(API) | alert / agent | 双机部署-爬虫机（仅暴露 REST） |
| `dual_machine_control` (C) | scheduler + storage + alert + agent + web_ui | core.crawler（远程调用爬虫机） | 双机部署-控制机 |
| `offline` (D) | core + storage + scheduler + local_landing | alert / agent / web_ui（无外网） | 完全离线模式（仅本地落地） |

> **实施优先级**：**D 优先 → A/B → 最后 C**。先打通离线保底链路，再扩展联网能力，最后处理双机分布式形态。

### 4.2 部署模式枚举与模块开关

```python
# config/deploy_mode.py

    STANDALONE_WIRED = "standalone_wired"            # A: 单机+有线

    DUAL_MACHINE_CRAWLER = "dual_machine_crawler"    # C: 双机-爬虫机
    DUAL_MACHINE_CONTROL = "dual_machine_control"    # C: 双机-控制机

class ModuleToggle(BaseModel):
    """各模块启停开关（由配置文件控制）"""
    crawler: bool = True
    network: bool = True
    scheduler: bool = True
    local_landing: bool = True
    alert_gateway: bool = False    # 需外网
    agent: bool = False            # 可拆卸，需外网
    web_ui: bool = False           # 可选
```

### 4.4 配置加载（settings.py）

`settings.py` 通过 `--config` 参数加载指定的 yaml 文件，并完成 `inherits` 字段的递归合并。

```python
# config/settings.py
import argparse
import yaml
from pathlib import Path
from pydantic import Field
from pydantic_settings import BaseSettings
from config.deploy_mode import DeployMode, ModuleToggle


class PlatformSettings(BaseSettings):
    domain: str = "pm.gd.csg.cn"


class StorageSettings(BaseSettings):
    data_dir: str = "./data"
    sqlite_path: str = "./data/spider.db"
    enable_wal: bool = True


class LogSettings(BaseSettings):
    persist_to_file: bool = True
    file_dir: str = "./logs"
    console_level: str = "INFO"
    file_level: str = "DEBUG"
    retention_days: int = 30


class AlertSettings(BaseSettings):
    channels: list[dict] = []


class AppSettings(BaseSettings):
    """根配置：从 yaml 加载"""
    deploy_mode: DeployMode = DeployMode.OFFLINE
    modules: ModuleToggle = Field(default_factory=ModuleToggle)
    platform: PlatformSettings = Field(default_factory=PlatformSettings)
    storage: StorageSettings = Field(default_factory=StorageSettings)
    log: LogSettings = Field(default_factory=LogSettings)
    alert: AlertSettings = Field(default_factory=AlertSettings)


def _load_yaml(path: Path) -> dict:
    with open(path, "r", encoding="utf-8") as f:
        data = yaml.safe_load(f) or {}
    inherits = data.pop("inherits", None)
    if inherits:
        base = _load_yaml(path.parent / inherits)
        base.update(data)  # 子文件覆盖父文件
        return base
    return data


def load_config(config_path: str) -> AppSettings:
    raw = _load_yaml(Path(config_path))
    return AppSettings(**raw)


def parse_cli() -> AppSettings:
    parser = argparse.ArgumentParser()
    parser.add_argument("--config", required=True, help="yaml 配置文件路径")
    args = parser.parse_args()
    return load_config(args.config)
```

### 4.5 主程序启动入口（Agent 可拆卸装配）

```python
# main.py
import asyncio
from loguru import logger
from config.settings import parse_cli


async def start_app(settings):
    # 核心模块（始终启动）
    from core.crawler.api_fetcher import ApiFetcher
    from core.scheduler.task_scheduler import TaskScheduler
    from infrastructure.storage.database import TaskStateStore
    from infrastructure.storage.local_landing import LocalLanding

    crawler = ApiFetcher(settings)
    scheduler = TaskScheduler(settings)
    storage = TaskStateStore(settings)
    landing = LocalLanding(settings)

    # 网络模块（根据配置）
    if settings.modules.network:
        from infrastructure.network.diagnoser import NetworkManager
        network = NetworkManager(settings)

    # 告警（需外网，离线模式下禁用）
    if settings.modules.alert_gateway:
        from gateway.alert.alert_gateway import AlertGateway
        alert = AlertGateway(settings)
    else:
        from gateway.alert.alert_gateway import NullAlertGateway
        alert = NullAlertGateway()  # 空实现，不报错

    # Agent（可拆卸，完全可选）
    if settings.modules.agent:
        from gateway.agent.agent_adapter import AgentAdapter
        agent = AgentAdapter(settings)
        logger.info("Remote Agent module loaded (permission level: {})",
                    settings.agent.max_permission)
    else:
        agent = None
        logger.info("Remote Agent module disabled")

    await scheduler.start()
    await asyncio.Event().wait()


if __name__ == "__main__":
    settings = parse_cli()
    asyncio.run(start_app(settings))
```

> **设计要点**：业务模块永远不写 `if mode == ...:`，全部通过 `settings.modules.*` 决定装配；Agent 关闭时不影响主流程，告警关闭时使用 `NullAlertGateway` 空实现兜底。

## 5. 模块间通信设计

### 5.1 场景一：单机模式 — 直接函数调用

所有模块运行在同一 Python 进程内，通过 Protocol 接口直接调用，**零网络开销**。

```
┌─────────────────────────────────────────────────────┐
│              单一 Python 进程 (main.py)              │
│                                                     │
│  Scheduler ──call──▶ ICrawler ──save──▶ IStorage    │
│                                                     │
│  DingTalkBot ──call──▶ ICrawler / IStorage          │
└─────────────────────────────────────────────────────┘
```

**优点**：实现简单、无序列化开销、调试友好。
**缺点**：模块崩溃可能拖死进程（通过 `try/except` + 子进程隔离缓解）。

### 5.2 场景二：双机模式 — HTTP API 通信

爬虫机暴露 FastAPI 服务，控制机通过 `httpx` 客户端调用。

**爬虫机暴露接口：**

| 路径 | 方法 | 功能 |
|------|------|------|
| `POST /api/crawl/start` | POST | 启动一次采集任务 |
| `GET /api/crawl/status/{task_id}` | GET | 查询任务状态 |
| `GET /api/data/download` | GET | 下载已采集数据（按日期/类型筛选） |
| `GET /api/health` | GET | 健康检查 |
| `POST /api/session/refresh` | POST | 强制刷新 Token |

**请求/响应示例：**

```json
// POST /api/crawl/start
{
  "task_id": "T20260619001",
  "date": "20260618",
  "data_type": "daily_settlement",
  "priority": 1
}

// 响应
{
  "code": 0,
  "msg": "ok",
  "data": {
    "task_id": "T20260619001",
    "status": "running",
    "submitted_at": "2026-06-19T09:00:00+08:00"
  }
}
```

**控制机调用代理（实现 ICrawler）：**

```python
# gateway/api/remote_crawler_proxy.py
import httpx
from interfaces.crawler_protocol import ICrawler, CrawlTask, CrawlResult


class RemoteCrawlerProxy:
    """控制机通过 HTTP 调用爬虫机时使用的代理"""

    def __init__(self, base_url: str, token: str):
        self._client = httpx.AsyncClient(
            base_url=base_url,
            timeout=300,
            headers={"Authorization": f"Bearer {token}"},
        )

    async def login(self) -> bool:
        r = await self._client.post("/api/session/login")
        return r.json().get("code") == 0

    async def fetch_data(self, task: CrawlTask) -> CrawlResult:
        r = await self._client.post("/api/crawl/start", json=task.__dict__)
        body = r.json()
        return CrawlResult(
            task_id=task.task_id,
            success=body["code"] == 0,
            data=None,           # 数据通过另一接口下载
            record_count=body.get("data", {}).get("record_count", 0),
            error_msg=body.get("msg"),
        )

    async def get_session_status(self) -> dict:
        r = await self._client.get("/api/health")
        return r.json().get("data", {})

    async def refresh_token(self) -> bool:
        r = await self._client.post("/api/session/refresh")
        return r.json().get("code") == 0
```

**优点**：物理隔离、爬虫机崩溃不影响控制机；可独立扩容。
**缺点**：需要处理网络异常、序列化、鉴权。

### 5.3 场景三：离线模式 — 本地落地

无任何外部网关，采集结果直接写入本地任务目录，SQLite 仅记录状态。**不需要同步队列与后台 flush 逻辑**，遵循 SQLite 与 Excel 职责分离原则。

```
┌──────────────────────────────────────────────┐
│  Crawler ──save_data_file─▶ ./data/{年月日}/任务名/*.xlsx │
│                       │                      │
│                       │  ITaskStateStore       │
│                       │   update_item_status() │
│                       ▼                      │
│           ┌─────────────────────┐            │
│           │ ILocalLanding       │            │
│           └─────────────────────┘            │
│                       │ 生成台账与zip          │
│                       ▼                      │
│           台账.xlsx + 任务目录.zip          │
└──────────────────────────────────────────────┘
```

`offline_cache.py` 的核心数据结构（仅记录状态，不存储业务数据）：

```sql
CREATE TABLE IF NOT EXISTS tasks (
    task_id     TEXT PRIMARY KEY,
    name        TEXT NOT NULL,
    status      TEXT NOT NULL,           -- pending/running/completed/failed
    output_dir  TEXT NOT NULL,
```

> **说明**：业务数据以 Excel 文件形式落地到 `./data/{年月}/{年月日}/{任务名}_{执行时间}/`，台账 xlsx 与任务目录 zip 由 `ILocalLanding` 生成。

## 9. 错误处理与恢复策略

### 9.1 模块级错误隔离

每个模块的入口方法都用 `try/except` 包裹，**绝不让异常向上穿透到 main 循环**。

```python
# 示例：钉钉 Bot 的消息处理
async def on_message(self, msg: dict) -> str:
    try:
        return await self._command_parser.handle(msg)
    except Exception as e:
        logger.exception(f"钉钉消息处理失败: {e}")
        await self._monitor.alert(
            HealthLevel.WARN, "钉钉指令异常", str(e)
        )
        return "处理失败，请联系管理员"
```

### 9.2 全局异常处理器（FastAPI）

```python
# gateway/api/server.py
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()

@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    logger.exception(f"未捕获异常: {request.url} -> {exc}")
    return JSONResponse(
        status_code=500,
        content={"code": -1, "msg": "internal error", "data": None},
    )
```

### 9.3 优雅降级策略

| 故障场景 | 降级行为 |
|---------|---------|
| 告警网关不可用 | 使用 `NullAlertGateway` 空实现，仅记录本地日志，主流程继续 |
| 验证码识别失败 | 自动重试（最多 5 次），仍失败转人工告警 |
| 网络断开 | 进入离线模式，仅本地落地，台账与 zip 仍可生成；告警震荡合并 |
| API 接口失败 | 回退到 Playwright 浏览器方案 |
| Token 失效 | 重新调用 `login_flow.execute()` 获取新 session |
| Agent 调用超限 | `permission_guard.check()` 返回 False，记录到审计日志不执行 |
| SQLite 锁等待超时 | 指数退避重试（基于 `retry_policy.py`） |

### 9.4 重试策略（指数退避）

```python
# core/scheduler/retry_policy.py
import asyncio
import random
from typing import Callable, Awaitable, TypeVar

T = TypeVar("T")


async def retry_with_backoff(
    func: Callable[[], Awaitable[T]],
    max_retries: int = 3,
    base_delay: float = 1.0,
    max_delay: float = 60.0,
    jitter: bool = True,
) -> T:
    """指数退避 + 抖动"""
    last_exc: Exception | None = None
    for attempt in range(max_retries):
        try:
            return await func()
        except Exception as e:
            last_exc = e
            delay = min(base_delay * (2 ** attempt), max_delay)
            if jitter:
                delay *= 0.5 + random.random()
            logger.warning(f"第 {attempt + 1} 次失败，{delay:.1f}s 后重试: {e}")
            await asyncio.sleep(delay)
    raise last_exc  # type: ignore
```

## 10. 安全考虑

### 10.1 凭据管理

- **绝不硬编码** Token / 密码 / 密钥到代码或仓库；
- 所有敏感信息通过 `.env` 文件读取，`.env` 加入 `.gitignore`；
- 提供 `.env.example` 作为模板（仅含字段名，不含真值）；
- 生产环境建议结合 Windows 凭据管理器或加密文件存储。

### 10.2 日志脱敏

```python
# 在 loguru 中注册过滤器
import re
from loguru import logger

SENSITIVE_PATTERNS = [
    (re.compile(r'(password["\s:=]+)([^"\s,}]+)', re.I), r'\1***'),
    (re.compile(r'(token["\s:=]+)([^"\s,}]+)', re.I), r'\1***'),
    (re.compile(r'(HdKGccbL["\s:=]+)([^"\s,}]+)'), r'\1***'),
    (re.compile(r'(\d{17}[\dxX])'), r'***身份证***'),
]


def mask_sensitive(record):
    msg = record["message"]
    for pattern, repl in SENSITIVE_PATTERNS:
        msg = pattern.sub(repl, msg)
    record["message"] = msg
    return True


logger.remove()
logger.add("logs/app_{time:YYYY-MM-DD}.log",
           filter=mask_sensitive, rotation="00:00", retention="30 days")
```

### 10.3 SQLite 文件权限

- 仅服务运行账户可读写 `data/spider.db`；
- 通过 `icacls` 命令在安装时设置 NTFS 权限；
- 离线缓存中的敏感字段（如包含登录态的 payload）使用对称加密（可选 `cryptography.fernet`）。

```bat
:: deploy/install.bat 片段
icacls "data\spider.db" /inheritance:r
icacls "data\spider.db" /grant:r "%USERNAME%":(F)
icacls "data\spider.db" /deny "Everyone":(R,W)
```

### 10.4 双机 HTTP 通信鉴权

- 爬虫机 REST API 强制要求 `Authorization: Bearer <api_token>`；
- Token 通过 `.env` 配置，不出现在 URL 或日志中；
- 仅监听内网网段（`uvicorn --host 192.168.x.x`），禁止公网暴露；
- 启用 HTTPS（推荐自签证书 + 证书校验）。

### 10.5 验证码与 OCR 安全

- `ddddocr` 模型为本地推理，不上传任何图片到第三方；
- 验证码图片在识别完成后立即从内存释放，不落盘。

### 10.6 远程 Agent 权限与审计

针对可拆卸的 `gateway/agent/`，采用**三级权限 + 全量审计 + 高危二次确认**三重保障：

| 权限级别 | 范围 | 默认状态 | 交付要求 |
|---------|------|---------|---------|
| `readonly` | 查询任务状态、读取台账、检查健康状态 | 默认开放 | 无需额外确认 |
| `config` | 修改调度计划、手动触发任务、调整告警阈值 | 需二次确认 | 必须交互文本验证码或钉钉审批 |
| `system` | OTA升级、重启服务、卸载模块、修改路由表 | 交付时锁死 | 默认拒绝，需运维人员在本地手动解锁 |

```python
# gateway/agent/permission_guard.py 示例
class PermissionGuard:
    LEVELS = {"readonly": 0, "config": 1, "system": 2}

    def __init__(self, max_level: str = "readonly"):
        self._max = self.LEVELS[max_level]

    def check(self, command_level: str) -> bool:
        return self.LEVELS[command_level] <= self._max
```

**审计与二次确认：**
- 所有 Agent 指令（含被拒绝的）必须追加到 `logs/agent_audit_{YYYYMMDD}.log`，记录时间/发起者/指令原文/权限判定结果/执行耗时，保留90天；
- `config` 及以上级别需要二次确认：向钉钉推送一条含唯一 token 的确认消息，超时 60s 未确认则判定为拒绝；
- OTA 升级、服务重启、卸载模块等高危操作默认仅记录日志不执行，必须运维人员在本地设置 `agent.max_permission=system` 后才可生效。
