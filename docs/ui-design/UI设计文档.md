# 广东电力数据采集系统 — UI 设计文档

> **设计目标**：打开即用，零学习成本。用户插 U-Key，软件自动登录、自动采集、自动补漏。用户只需看一眼"齐不齐"，不齐点补采，齐了拿文件。
>
> **技术栈**：React + Ant Design + Electron（后期打包 exe）

---

## 1. 整体布局

侧边栏极窄（icon-only），不抢内容区空间。顶栏只放系统名称和全局状态。

```
+======================================================+
|  广东电力数据采集            [U-Key ●已连接] [网络 ●正常] |
+------+-----------------------------------------------+
|      |                                               |
|  🏠  |                                               |
|  首页 |              主内容区                          |
|      |         （根据左侧选中项切换）                   |
|  📁  |                                               |
|  文件 |                                               |
|      |                                               |
|  📋  |                                               |
|  任务 |                                               |
|      |                                               |
|  🤖  |                                               |
|  助手 |                                               |
| (预留)|                                               |
|      |                                               |
|  ──  |                                               |
|  ⚙️  |                                               |
|      |                                               |
+------+-----------------------------------------------+
```

**说明**：

| 区域   | 内容                                         |
| ------ | -------------------------------------------- |
| 顶栏   | 系统名称 + U-Key 状态 + 网络状态              |
| 侧边栏 | 4 个功能项（首页/文件/任务/助手）+ 底部设置图标 |
| 主内容 | 根据侧边栏选中项切换页面                       |

**侧边栏细节**：

- 宽度 56px，icon-only 模式，hover 显示文字 tooltip
- 🤖助手：V1.0 灰色不可点，显示"即将上线"，预留 Dify/MaxKB 接入
- ⚙️设置：点击弹出设置 Modal（不是独立页面）

**顶栏状态指示灯**：

- U-Key：绿色=已连接 / 红色=未插入 / 黄色=识别中
- 网络：绿色=正常 / 红色=断开
- 不放多余信息，保持极简

### 2.2 版本机制说明

| 场景 | 行为 | 界面展示 |
| --- | --- | --- |
| 首次采集到文件 | 生成版本号 `v{MMdd}-{HHmm}` | 显示版本号 + ✓已采集 |
| 再次采集，hash 相同 | 不更新，不新增版本 | 版本号不变 |
| 再次采集，hash 不同 | 保留旧版本，新增新版本 | 显示多版本标记 🔀 |
| 采集为空 / 失败 | 标记缺失 | 显示 ✗缺失 + [上传] 按钮 |

**多版本文件展示**：当某文件存在多个版本时，名称后显示 🔀 标记，点击可展开版本列表：

```
|    ├ 日前出清电价查询(2026-06-22).xlsx  🔀多版本       |
|    │   ├─ v0622-1430  (最新)  156KB  [📥]            |
|    │   └─ v0622-0900  (旧)    148KB  [📥]            |
```

### 2.3 缺失数据处理

缺失的文件在 TreeTable 中单独标注（灰色 + ✗ 图标），用户有两种补救方式：

**方式一：自动补采**
- 点击顶部 [⚡ 补采缺失]：系统自动重新触发一次采集，尝试获取所有缺失文件
- 采集过程弹出进度弹窗（见第5章）

**方式二：手动上传**
- 点击缺失文件行的 [⬆ 上传] 按钮，弹出上传 Dialog：

```
+-----------------------------------------------+
|  上传文件：日前节点电价(2026-06-22).xlsx [✕]  |
|-----------------------------------------------|
|                                               |
|  ┌───────────────────────────────────────┐   |
|  |                                       |   |
|  |    📂  拖拽文件到此处                  |   |
|  |       或 [点击选择文件]                |   |
|  |                                       |   |
|  |       支持 .xlsx .csv .pdf            |   |
|  |                                       |   |
|  └───────────────────────────────────────┘   |
|                                               |
|  文件名：日前节点电价查询_20260622.xlsx       |
|  大小：  156 KB                              |
|  匹配：  ✓ 文件名匹配预期                    |
|                                               |
|                       [取消]  [确认上传]      |
+-----------------------------------------------+
```

上传成功后：
- 界面上该文件状态从 `✗缺失` 变为 `✓已采集`（来源标注为"手动上传"）
- 顶部完成数 +1

### 2.4 设计要点

- **左右双栏**：左栏文件明细占 70% 宽度，右栏动态占 30%
- **TreeTable**：支持文件夹折叠/展开，层级对应实际数据目录结构
- **版本号格式**：`v{MMdd}-{HHmm}`（如 `v0622-1430`），用户友好，不是 timestamp
- **大数字**在顶部标题行（`10/12 已完成`），一眼看完成度
- **下载全部 ZIP**：打包当天所有已采集文件（含目录结构）为 zip 下载
- **缺失项显眼**：灰色 + ✗ 图标 + [上传] 按钮，不用跳转到别的页面
- **最新动态**：卡片式展示（时间 + 标题 + 描述），不是终端风格，用户友好
- **一键补采**：触发程序自动重新采集缺失项（走正常采集流程）

- 工具栏右侧 ☰ 列表 / ▦ 宫格 切换图标
- [打开下载目录]：直接调系统文件管理器，最直接的"拿文件"方式
- 上传时自动识别文件名/内容归类，识别不了让用户手选
- 支持拖拽批量上传
- 搜索：在当前文件列表中按文件名过滤
- 不搞分栏视图、不搞外传记录 — V1.0 不需要

**最小化后（右下角悬浮气泡）**：

```
                    +---------------------------+
                    | ● 采集中  日前出清  4/6   |
                    +---------------------------+
```

**设计要点**：

- 步骤进度条 + 节点状态：✓已完成 / ●进行中 / ○未开始
- 只显示关键业务日志（登录成功、导航完成、下载完成、异常等）
- 不是 debug 级全量日志，是用户能理解的业务节点
- [后台运行]：最小化到右下角悬浮气泡，不打断用户操作
- [取消]：安全终止当前采集
- 完成后自动关闭弹窗，首页状态刷新
