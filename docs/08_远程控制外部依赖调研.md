# 远程控制外部依赖调研（阶段 1 排雷）

> 目的：阶段 3 才实现 Agent 双向通信与统一控制接口，但其外部依赖（权限申请、SDK、部署环境）
> 周期长、易卡壳。本文在阶段 1 提前调研、定方案，避免到阶段 3 才发现权限要走两周流程。
> 结论先行：阶段 3 默认走「钉钉自定义机器人 Webhook（已实现，单向）+ 钉钉 Stream（双向，需企业应用）」，
> OpenClaw/龙虾作为可选适配器，依赖现场是否提供接入端点。

## 1. 钉钉接入两种形态对比

| 维度 | 群自定义机器人 Webhook（现状） | 企业应用 + Stream 模式（目标） |
|------|------------------------------|-------------------------------|
| 方向 | 单向（系统→群） | 双向（群/单聊 ↔ 系统） |
| 凭据 | Webhook URL + 加签 secret | AppKey + AppSecret（企业应用） |
| 申请方 | 群管理员即可添加 | 需企业管理员在开放平台创建应用并授权 |
| 出网 | 仅需访问 `oapi.dingtalk.com` | Stream 走 WebSocket 长连，访问 `api.dingtalk.com` |
| 代码现状 | 已实现 `gateway/alert/webhook_sender.py`（HMAC-SHA256 加签） | 未实现，SDK 依赖 `dingtalk-stream`（已在 `pyproject.toml` online extra 声明） |
| 适用 | 告警推送 | 远程指令（"立即采集""查状态"）回传执行结果 |

### 阶段 3 落地前需确认（请业务/IT 提前申请）
- [ ] 是否有企业钉钉开放平台管理员权限，可创建「企业内部应用」。
- [ ] 应用获取 `AppKey` / `AppSecret`，开通「机器人」能力与「Stream 模式」。
- [ ] 采集笔记本的公网网卡可访问 `api.dingtalk.com`（Stream 长连）。双网卡场景下，
      告警/Agent 流量应走 WiFi/有线公网网卡，不走专网（与现有路由策略一致）。
- [ ] 确认消息接收人/群范围与指令白名单（与 `permission_guard` 三级权限对齐）。

### 依赖与出网
- Python 包：`dingtalk-stream>=0.20`（online extra，已声明，未安装到核心环境）。
- 出网域名：`oapi.dingtalk.com`（webhook）、`api.dingtalk.com`（Stream/token）。
- 失败兜底：Stream 不可用时自动降级为现有单向 Webhook 告警，不阻断采集主流程。

## 2. OpenClaw / 龙虾 Agent

| 项 | 现状/结论 |
|----|-----------|
| 接入形态 | 通过统一控制接口（阶段 3 的 REST/WebSocket）或专用适配器接入；指令经 `gateway/agent` 解析。 |
| 代码现状 | `gateway/agent/agent_adapter.py` 的 `send_response` 仅记录日志，预留回传位。 |
| 阻塞点 | 需现场确认龙虾/Codex 类 Agent 的接入端点、鉴权方式（API Key/Token）、回调协议。 |
| 建议 | 阶段 3 先把 REST API（`/api/crawl/start`、`/api/health`、`/api/tasks`）作为通用控制面，
        任何 Agent（含龙虾/Codex）均可通过 HTTP 调用；钉钉 Stream 作为人机交互通道。 |

### 阶段 3 落地前需确认
- [ ] 龙虾/Codex Agent 运行在何处？是否与采集笔记本同网段或经公网回调？
- [ ] 鉴权：Agent 调用统一接口的 Token 由谁签发、如何轮换。
- [ ] 是否需要服务端主动 push（WebSocket）还是 Agent 轮询 REST 即可。

## 3. 风险与排期建议

| 风险 | 影响 | 缓解 |
|------|------|------|
| 企业应用权限审批慢 | 阻塞双向通信 | 阶段 1 即提交申请；阶段 3 前完成。期间用单向 Webhook 顶住告警需求。 |
| 双网卡出网受限 | Stream 长连失败 | 复用现有路由策略，确保公网网卡可达钉钉域名；不可达时降级单向。 |
| 龙虾接入协议未知 | 适配器无法实现 | 以通用 REST 控制面为主，龙虾适配器作为可选插件，协议明确后再补。 |

## 4. 一句话结论

阶段 3 的远程控制不依赖任何阻塞性新技术：**REST 控制面 + 钉钉 Stream（企业应用）**为主路径，
现有单向 Webhook 为降级兜底，OpenClaw/龙虾以通用 HTTP 适配接入。唯一需要提前推进的是
**企业钉钉应用的权限申请**——建议立即启动。
