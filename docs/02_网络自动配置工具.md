> 子系统名称：U-Key 网络管理模块（Network Auto Configurator）
> 所属项目：广东电力交易数据智能采集系统
> 版本：v1.0
> 状态：设计稿

---

## 1. 概述

### 1.1 背景问题

广东电力交易中心采用专网接入方式，运维终端通过 **U-Key（USB 随身 WiFi 设备）** 接入专网 `pm.gd.csg.cn`。该方案存在以下天然冲突：

| 痛点 | 描述 |
| --- | --- |
| U-Key 插入后外网断开 | 最常见的情况是 Windows 将 WiFi 设为默认网关（`0.0.0.0/0`），但底层机制可能因驱动/系统版本而异（如 metric 抢占、DNS 被覆盖等），需通过现场诊断确认 |
| 无法双网并存 | 系统同时需要"专网拉数据"+"外网访问内部 OA / 推送告警"，原生不支持 |
| 手动配置易错 | 涉及 `route delete` / `route add` / Metric 调整，运维人员极易输错网关 IP |
| 重启即失效 | 手动添加的路由默认非持久化，重启或拔插 U-Key 后全部失效 |
| 拔插事件无人响应 | U-Key 拔出后专网路由残留，再次插入分配的 IP 可能变化，需重新探测 |

### 1.2 设计目标

构建一套**零接触、自愈式**的网络自动化配置工具，实现：

1. **检测 U-Key**：USB 设备插入事件秒级感知，并记录插入前路由表快照
2. **自动诊断网络**：对比 U-Key 插入前后的路由表/适配器变化，自动定位断网根因（不依赖对底层机制的任何假设）
3. **获取专网 IP**：**显式指定 WiFi 网卡的 DNS 服务器**解析 `pm.gd.csg.cn`（专网域名公网 DNS 解析不了）
4. **配置路由表**：根据诊断结论修复路由（如删除被抢占的默认路由）、添加专网精确路由（`/32`）、保留外网默认路由
5. **验证双网络**：同时验证专网可达 + 外网可达，输出 JSON 报告
6. **拔出自清理**：U-Key 拔出立即清理残留路由

## 3. 核心自动化流程（6 步）

### Step 1：检测 U-Key 插入

#### 3.1.1 技术方案

使用 WMI 的 `Win32_USBHub` 进行**轮询**（2~5 秒间隔）。相比 `__InstanceCreationEvent` 异步事件，轮询更稳定、不受权限策略限制。

#### 3.1.2 VID/PID 匹配

- 配置文件中可指定 `ukey_vid_pid: "148F:5370"`
- 设为 `auto` 时启用**自动发现模式**：第一次插入新 USB 设备时弹窗（独立 exe 模式）或写入候选列表（服务模式），由用户确认

#### 3.1.3 Python 代码示例

```python
# src/route_manager/usb_watcher.py
import wmi
import time
from loguru import logger

class USBWatcher:
    def __init__(self, vid_pid: str = "auto", poll_interval: int = 3):
        self.vid_pid = vid_pid.upper() if vid_pid != "auto" else None
        self.poll_interval = poll_interval
        self.c = wmi.WMI()
        self._last_devices = set()
        self._running = False

    def _list_usb_ids(self) -> set[str]:
        """列出当前连接的所有 USB 设备 ID（VID:PID 格式）"""
        ids = set()
        for hub in self.c.Win32_PnPEntity(ConfigManagerErrorCode=0):
            did = hub.DeviceID or ""
            # 解析格式: USB\VID_148F&PID_5370\...
            if "VID_" in did and "PID_" in did:
                vid = did.split("VID_")[1][:4]
                pid = did.split("PID_")[1][:4]
                ids.add(f"{vid}:{pid}")
        return ids

    def _is_ukey(self, vid_pid: str) -> bool:
        if self.vid_pid is None:
            return True  # auto 模式，下游进一步过滤
        return vid_pid == self.vid_pid

    def watch(self, on_inserted, on_removed):
        self._running = True
        self._last_devices = self._list_usb_ids()
        logger.info(f"USB 监听启动，初始设备数={len(self._last_devices)}")

        while self._running:
            time.sleep(self.poll_interval)
            try:
                current = self._list_usb_ids()
                added = current - self._last_devices
                removed = self._last_devices - current

                for d in added:
                    if self._is_ukey(d):
                        logger.success(f"U-Key 插入：{d}")
                        on_inserted(d)

                for d in removed:
                    if self._is_ukey(d):
                        logger.warning(f"U-Key 拔出：{d}")
                        on_removed(d)

                self._last_devices = current
            except Exception as e:
                logger.exception(f"USB 轮询异常：{e}")

    def stop(self):
        self._running = False
```

#### 3.1.4 自动发现 VID/PID

```python
def auto_discover(timeout=60):
    """提示用户拔出再插入 U-Key，记录新增的设备 ID"""
    watcher = USBWatcher(vid_pid="auto")
    before = watcher._list_usb_ids()
    print("请拔出 U-Key，5 秒后再插入...")
    time.sleep(timeout)
    after = watcher._list_usb_ids()
    diff = after - before
    if len(diff) == 1:
        new_id = diff.pop()
        print(f"已捕获 U-Key：{new_id}")
        return new_id
    raise RuntimeError(f"无法唯一确定 U-Key，新增设备 {diff}")
```

#### 3.1.5 启动时记录路由表"插入前快照"

服务模式 / 独立 exe 在 USBWatcher 启动后**立即采样一次"基线快照"**（在等待 U-Key 插入事件之前），保存当前默认路由 / 网络适配器 / DNS 服务器状态，供 Step 3 自动诊断使用：

```python
# 服务模式启动入口示例
from route_manager.diagnoser import NetSnapshot

service.baseline = NetSnapshot.take()        # ← 插入前快照（基线）
service.usb_watcher.watch(
    on_inserted=service.on_ukey_inserted,    # 插入后立刻再采一次 NetSnapshot 用于对比
    on_removed=service.on_ukey_removed,
)
```

> 即使主程序启动时 U-Key 已经在插着的状态，也能在"提示拔出 → 用户拔出 → 程序记录基线 → 提示插入 → 用户插入"的循环里重新校准基线，保证诊断对比有效。

### Step 2：等待 WiFi 连接建立

#### 3.2.1 监控逻辑

USB 插入到 WiFi 真正 Up（拿到 IP）通常有 2~10 秒延迟，必须**轮询等待**直至 Up 或超时（默认 30 秒）。

#### 3.2.2 PowerShell 命令

```powershell
Get-NetAdapter -Name "Wi-Fi" | Select-Object -ExpandProperty Status
# 返回：Up / Down / Disconnected
```

#### 3.2.3 Python 代码示例

```python
# src/route_manager/wifi_waiter.py
import subprocess
import time
from loguru import logger

def wait_wifi_up(interface: str = "Wi-Fi", timeout: int = 30) -> bool:
    deadline = time.time() + timeout
    while time.time() < deadline:
        ps = (
            f'Get-NetAdapter -Name "{interface}" '
            f'| Select-Object -ExpandProperty Status'
        )
        try:
            r = subprocess.run(
                ["powershell", "-NoProfile", "-Command", ps],
                capture_output=True, text=True, timeout=5
            )
            status = r.stdout.strip()
            logger.debug(f"WiFi[{interface}] 状态={status}")
            if status == "Up":
                logger.success(f"WiFi 已连接，用时 {timeout - (deadline - time.time()):.1f}s")
                return True
        except subprocess.TimeoutExpired:
            logger.warning("PowerShell 查询超时")
        time.sleep(1)
    logger.error(f"WiFi 连接超时（{timeout}s）")
    return False
```

### Step 3：自动网络诊断（不假设原因，按现场对比修复）

#### 3.3.1 设计思路

> **核心原则**：本工具**不依赖对 U-Key / 驱动行为的任何假设**，而是通过**对比 U-Key 插入前后的路由表与适配器状态**，自动发现差异并据此修复——不管底层机制是什么，最终效果都是"专网流量走 WiFi、外网流量走有线/4G"。

现场实际观测中，U-Key 插入后导致外网断开的可能机制包括（按概率排序）：

- **最常见**：WiFi 接口被分配了 `0.0.0.0/0` 默认路由，抢占整机默认出口
- **次常见**：WiFi 默认路由 metric 优于既有有线 / 4G，被系统优先选用
- **偶发**：DNS 服务器被切换为 WiFi 提供的内网 DNS，导致公网域名解析失败
- **其他**：驱动差异、企业终端策略二次覆盖等

本步骤的实现**不预判**究竟是哪一种，而是通过"前后快照 diff → 自动得出结论 → 调用对应修复动作"完成自愈。

#### 3.3.2 三阶段诊断流程

**阶段 ①：插入前快照**（在 Step 1 等待事件之前 / 服务启动时记录，参见 3.1.5）

```powershell
# 记录当前默认路由（0.0.0.0/0）
$before_routes = Get-NetRoute |
    Where-Object { $_.DestinationPrefix -eq "0.0.0.0/0" } |
    Select-Object DestinationPrefix, NextHop, InterfaceAlias, RouteMetric, ifIndex

# 记录当前网络适配器状态
$before_adapters = Get-NetAdapter |
    Select-Object Name, Status, InterfaceMetric, ifIndex

# 记录当前各网卡的 DNS 服务器
$before_dns = Get-DnsClientServerAddress -AddressFamily IPv4 |
    Select-Object InterfaceAlias, ServerAddresses
```

**阶段 ②：插入后快照**（Step 2 完成、WiFi 状态变为 Up 后立即采样）

```powershell
$after_routes   = Get-NetRoute | Where-Object { $_.DestinationPrefix -eq "0.0.0.0/0" } | ...
$after_adapters = Get-NetAdapter | ...
$after_dns      = Get-DnsClientServerAddress -AddressFamily IPv4 | ...

# 对比差异
$route_diff   = Compare-Object $before_routes   $after_routes   -Property DestinationPrefix, NextHop, InterfaceAlias, RouteMetric
$adapter_diff = Compare-Object $before_adapters $after_adapters -Property Name, Status, InterfaceMetric
$dns_diff     = Compare-Object $before_dns      $after_dns      -Property InterfaceAlias, ServerAddresses
```

**阶段 ③：自动诊断结论**（基于 diff 自动推断根因 + 修复动作）

| diff 特征 | 诊断结论 | 自动修复动作 |
| --- | --- | --- |
| `after` 新增 WiFi 接口的 `0.0.0.0/0` 路由 | WiFi 默认网关抢占（最常见） | 删除该 WiFi 默认路由 |
| 既有有线 `0.0.0.0/0` 的 metric 变高 / WiFi 同名路由 metric 更低 | metric 抢占 | 还原有线 metric 或抬升 WiFi metric |
| WiFi 没有默认路由但外网仍不通 | 可能 DNS 被覆盖或上层策略干预 | 检查 / 强制还原原 DNS |
| 路由表无明显抢占，仅新增非默认路由 | 仅"加路由"，无抢占 | 无需修复，直接进入 Step 5 |

**关键点**：无论命中哪一条结论，都会进入 Step 5 的统一路由修复（添加专网 `/32` 精确路由），最终保证"专网走 WiFi、外网走原出口"。

#### 3.3.3 Python 代码示例

```python
# src/route_manager/diagnoser.py
import subprocess, json
from dataclasses import dataclass, field
from datetime import datetime
from loguru import logger


def _ps_json(cmd: str) -> list:
    r = subprocess.run(
        ["powershell", "-NoProfile", "-Command", f"{cmd} | ConvertTo-Json -Compress"],
        capture_output=True, text=True, timeout=10,
    )
    out = r.stdout.strip()
    if not out:
        return []
    data = json.loads(out)
    return data if isinstance(data, list) else [data]


@dataclass
class NetSnapshot:
    timestamp: str
    default_routes: list = field(default_factory=list)
    adapters: list = field(default_factory=list)
    dns_servers: list = field(default_factory=list)

    @classmethod
    def take(cls) -> "NetSnapshot":
        return cls(
            timestamp=datetime.now().isoformat(),
            default_routes=_ps_json(
                'Get-NetRoute | Where-Object {$_.DestinationPrefix -eq "0.0.0.0/0"} '
                '| Select-Object DestinationPrefix,NextHop,InterfaceAlias,RouteMetric,ifIndex'
            ),
            adapters=_ps_json(
                'Get-NetAdapter | Select-Object Name,Status,InterfaceMetric,ifIndex'
            ),
            dns_servers=_ps_json(
                'Get-DnsClientServerAddress -AddressFamily IPv4 '
                '| Select-Object InterfaceAlias,@{n="Servers";e={$_.ServerAddresses -join ","}}'
            ),
        )


def diagnose(before: NetSnapshot, after: NetSnapshot, wifi_iface: str = "Wi-Fi") -> dict:
    """对比前后快照，输出诊断报告（不假设原因，按差异推断）"""
    report = {
        "timestamp": datetime.now().isoformat(),
        "wifi_iface": wifi_iface,
        "findings": [],
        "conclusion": "",
        "fix_actions": [],
    }

    before_keys = {(r.get("InterfaceAlias"), r.get("NextHop")) for r in before.default_routes}
    new_default = [
        r for r in after.default_routes
        if (r.get("InterfaceAlias"), r.get("NextHop")) not in before_keys
    ]
    wifi_new_default = [r for r in new_default if r.get("InterfaceAlias") == wifi_iface]

    if wifi_new_default:
        report["findings"].append(f"WiFi 接口新增默认路由：{wifi_new_default}")
        report["conclusion"] = "WiFi 默认网关抢占"
        report["fix_actions"].append("删除 WiFi 默认路由")
    else:
        before_map = {r["InterfaceAlias"]: r["RouteMetric"] for r in before.default_routes}
        after_map  = {r["InterfaceAlias"]: r["RouteMetric"] for r in after.default_routes}
        for iface, m_after in after_map.items():
            m_before = before_map.get(iface)
            if m_before is not None and m_after > m_before:
                report["findings"].append(f"{iface} 默认路由 metric {m_before} → {m_after}")
                report["conclusion"] = "metric 被 U-Key 抢占"
                report["fix_actions"].append(f"还原 {iface} metric 至 {m_before}")
                break
        if not report["conclusion"]:
            report["conclusion"] = "未检测到明显抢占（路由结构未变化），仅需追加专网 /32 路由"

    # 兜底动作：始终在 Step 5 统一执行专网 /32 路由写入
    report["fix_actions"].append("添加专网 /32 精确路由（Step 5 统一执行）")
    logger.info(f"诊断结论：{report['conclusion']}")
    return report
```

### Step 4：DNS 解析获取交易中心真实 IP（必须走 WiFi 网卡 DNS）

#### 3.4.1 设计要点

| 需求 | 实现 |
| --- | --- |
| **必须走 WiFi 网卡的 DNS** | `pm.gd.csg.cn` 是专网内部域名，公网 DNS（8.8.8.8、114.114.114.114）**解析不了**；必须先用 PowerShell `Get-DnsClientServerAddress` 取出 WiFi 网卡的 DNS 服务器，再用 `nslookup <domain> <dns>` / `Resolve-DnsName -Server <dns>` **显式指定**，不能依赖系统默认 DNS |
| 多 A 记录支持 | 解析返回 list，全部加入路由 |
| 三级回退策略 | ① 首选：WiFi 网卡 DNS 解析→ ② 次选：直接 ping 域名（系统可能已缓存）→ ③ 兜底：配置文件中的历史缓存 IP |
| 防 DNS 投毒 | 可配置允许的 IP 段（如 `36.137.0.0/16`），过滤异常解析结果 |

#### 3.4.2 PowerShell 示例

```powershell
# 1. 获取 WiFi 网卡被 DHCP 分配的 DNS 服务器地址
$wifi_dns = (Get-DnsClientServerAddress -InterfaceAlias "Wi-Fi" -AddressFamily IPv4).ServerAddresses
# 输出示例： 10.0.0.1, 10.0.0.2

# 2. 使用 WiFi 的 DNS 服务器解析专网域名
$result = Resolve-DnsName -Name "pm.gd.csg.cn" -Server $wifi_dns[0]

# 3. 或者用 nslookup
nslookup pm.gd.csg.cn $wifi_dns[0]
```

#### 3.4.3 Python 代码示例

```python
# src/route_manager/dns_resolver.py
import subprocess
import re
import yaml
from pathlib import Path
from loguru import logger


def get_wifi_dns(interface_name: str = "Wi-Fi") -> list[str]:
    """获取 WiFi 网卡被 DHCP 分配的 DNS 服务器地址（按顺序）"""
    r = subprocess.run(
        ["powershell", "-NoProfile", "-Command",
         f'(Get-DnsClientServerAddress -InterfaceAlias "{interface_name}" '
         f'-AddressFamily IPv4).ServerAddresses'],
        capture_output=True, text=True, timeout=5,
    )
    return [ip.strip() for ip in r.stdout.strip().splitlines() if ip.strip()]


def resolve_via_dns(domain: str, dns_server: str, timeout: int = 10) -> list[str]:
    """通过指定 DNS 服务器调用 nslookup 解析域名。

    输出中开头出现的 'Address: <dns_server>' 是 DNS 服务器自身地址，需排除。
    """
    r = subprocess.run(
        ["nslookup", domain, dns_server],
        capture_output=True, text=True, timeout=timeout,
    )
    ips = re.findall(r"Address:\s*(\d+\.\d+\.\d+\.\d+)", r.stdout)
    return [ip for ip in ips if ip != dns_server]


class DNSResolver:
    """专网域名解析器：**必须走 WiFi 网卡的 DNS 服务器**。

    公网 DNS（8.8.8.8 / 114.114.114.114）无法解析 `pm.gd.csg.cn`。
    三级回退策略：
      ① 首选：通过 WiFi DNS 解析
      ② 次选：DNS 解析失败时直接 ping 域名（系统可能已缓存）
      ③ 兜底：使用上次成功解析的缓存 IP（存于配置文件）
    """

    def __init__(self, domain: str, cache_path: Path, wifi_iface: str = "Wi-Fi"):
        self.domain = domain
        self.cache_path = cache_path
        self.wifi_iface = wifi_iface
        self._cache = self._load_cache()

    def _load_cache(self) -> list[str]:
        if self.cache_path.exists():
            data = yaml.safe_load(self.cache_path.read_text(encoding="utf-8")) or {}
            return data.get("cached_ips", [])
        return []

    def _save_cache(self, ips: list[str]):
        self.cache_path.write_text(
            yaml.safe_dump({"cached_ips": ips}, allow_unicode=True),
            encoding="utf-8",
        )

    def resolve(self) -> list[str]:
        # ① 首选：通过 WiFi 网卡 DNS 解析
        dns_servers = get_wifi_dns(self.wifi_iface)
        if not dns_servers:
            logger.warning(f"WiFi[{self.wifi_iface}] 未拿到 DNS 服务器地址")
        else:
            logger.info(f"使用 WiFi DNS {dns_servers} 解析 {self.domain}")
            for dns in dns_servers:
                try:
                    ips = resolve_via_dns(self.domain, dns)
                    if ips:
                        logger.success(f"DNS({dns}) {self.domain} -> {ips}")
                        self._cache = ips
                        self._save_cache(ips)
                        return ips
                except Exception as e:
                    logger.warning(f"DNS({dns}) 解析失败：{e}")

        # ② 次选：直接 ping 域名（系统可能已缓存解析结果）
        try:
            r = subprocess.run(
                ["ping", "-n", "1", "-w", "2000", self.domain],
                capture_output=True, text=True, timeout=5,
            )
            m = re.search(r"\[(\d+\.\d+\.\d+\.\d+)\]", r.stdout)
            if m:
                ip = m.group(1)
                logger.warning(f"DNS 解析失败，使用 ping 兜底得到 IP：{ip}")
                self._cache = [ip]
                self._save_cache(self._cache)
                return [ip]
        except Exception as e:
            logger.warning(f"ping 兜底失败：{e}")

        # ③ 兜底：历史缓存 IP
        if self._cache:
            logger.warning(f"全部解析失败，使用历史缓存 {self._cache}")
            return self._cache

        raise RuntimeError(f"无法解析 {self.domain}（WiFi DNS / ping / 缓存均失败）")
```

> ⚠️ 注意：**不要使用 `socket.getaddrinfo()`** 或任何隐式走系统默认 DNS 的接口。系统默认 DNS 可能是公网 DNS，解析不了专网域名，会报 NXDOMAIN 并诡异地使调试人员以为"应该能连但不能连"。

### Step 5：自动配置路由表

#### 3.5.1 路由策略

```
┌───────────────────────────────────────────────────────────────┐
│  目标网段              下一跳              网卡        Metric  │
├───────────────────────────────────────────────────────────────┤
│  0.0.0.0/0  (默认)     192.168.1.1         以太网       10    │← 外网
│  36.137.x.12/32        10.211.55.1         Wi-Fi         1    │← 专网
│  36.137.x.13/32        10.211.55.1         Wi-Fi         1    │← 专网
└───────────────────────────────────────────────────────────────┘
```

核心动作（依据 Step 3 诊断报告执行）：

1. 获取 WiFi 网关 IP
2. **根据诊断结论修复被抢占的路由**——最常见场景为删除 WiFi 接口在 Step 2 后出现的 `0.0.0.0/0` 默认路由；如为 metric 抢占则调整相应接口的 InterfaceMetric
3. 为每个专网 IP **添加** `/32` 精确路由，下一跳=WiFi 网关
4. **校验** 外网网卡仍存在 `0.0.0.0/0` 默认路由（然后 Step 6 统一验证）

#### 3.5.2 PowerShell 脚本

```powershell
# resources/configure_route.ps1
param(
    [string]$WifiIface = "Wi-Fi",
    [string]$WanIface  = "以太网",
    [string[]]$TargetIPs
)

$ErrorActionPreference = "Stop"

# 1. 取 WiFi 网关
$wifiCfg = Get-NetIPConfiguration -InterfaceAlias $WifiIface
$wifiGw  = $wifiCfg.IPv4DefaultGateway.NextHop
if (-not $wifiGw) { throw "WiFi 网关获取失败" }
Write-Host "[INFO] WiFi 网关 = $wifiGw"

# 2. 删除 WiFi 默认路由
Get-NetRoute -InterfaceAlias $WifiIface -DestinationPrefix "0.0.0.0/0" `
    -ErrorAction SilentlyContinue | ForEach-Object {
    Remove-NetRoute -InputObject $_ -Confirm:$false
    Write-Host "[OK ] 删除 WiFi 默认路由"
}

# 3. 添加专网 /32 路由
foreach ($ip in $TargetIPs) {
    $existed = Get-NetRoute -DestinationPrefix "$ip/32" -ErrorAction SilentlyContinue
    if ($existed) { Remove-NetRoute -InputObject $existed -Confirm:$false }
    New-NetRoute -DestinationPrefix "$ip/32" `
                 -InterfaceAlias $WifiIface `
                 -NextHop $wifiGw `
                 -RouteMetric 1 `
                 -PolicyStore ActiveStore | Out-Null
    Write-Host "[OK ] 添加专网路由 $ip/32 via $wifiGw"
}

# 4. 校验外网默认路由
$wanRoute = Get-NetRoute -InterfaceAlias $WanIface -DestinationPrefix "0.0.0.0/0" `
                         -ErrorAction SilentlyContinue
if (-not $wanRoute) {
    Write-Warning "外网默认路由缺失，请检查 $WanIface"
    exit 2
}
Write-Host "[OK ] 外网默认路由存在 via $($wanRoute.NextHop)"
exit 0
```

#### 3.5.3 Python 调用

```python
# src/route_manager/route_writer.py
import subprocess
import sys, ctypes
from pathlib import Path
from loguru import logger

PS_SCRIPT = Path(__file__).parent.parent / "resources" / "configure_route.ps1"

def is_admin() -> bool:
    try:
        return ctypes.windll.shell32.IsUserAnAdmin() != 0
    except Exception:
        return False

def ensure_admin():
    """非管理员则通过 ShellExecuteW 提权重启自身"""
    if is_admin():
        return
    logger.warning("当前非管理员，触发 UAC 提权 ...")
    ctypes.windll.shell32.ShellExecuteW(
        None, "runas", sys.executable, " ".join(sys.argv), None, 1
    )
    sys.exit(0)

def configure_routes(target_ips: list[str], wifi="Wi-Fi", wan="以太网") -> bool:
    if not is_admin():
        raise PermissionError("路由配置需要管理员权限")
    cmd = [
        "powershell", "-NoProfile", "-ExecutionPolicy", "Bypass",
        "-File", str(PS_SCRIPT),
        "-WifiIface", wifi,
        "-WanIface", wan,
        "-TargetIPs", ",".join(target_ips),
    ]
    logger.info("执行路由配置脚本 ...")
    r = subprocess.run(cmd, capture_output=True, text=True, timeout=30)
    logger.debug(r.stdout)
    if r.returncode == 0:
        logger.success("路由配置成功")
        return True
    logger.error(f"路由配置失败 rc={r.returncode}\n{r.stderr}")
    return False
```

### Step 6：自我验证

#### 3.6.1 验证项

| 项 | 命令 | 期望 |
| --- | --- | --- |
| 专网可达 | `Test-NetConnection pm.gd.csg.cn -Port 443` | `TcpTestSucceeded=True`，出口=WiFi |
| 外网可达 | `Test-NetConnection 8.8.8.8 -InformationLevel Quiet` | `True`，出口=有线 |
| 路由表正确 | `Get-NetRoute` | 存在专网 /32 路由 + 外网默认路由 |

#### 3.6.2 Python 实现

```python
# src/route_manager/verifier.py
import subprocess, json, time
from datetime import datetime
from loguru import logger

def _ps(cmd: str) -> str:
    r = subprocess.run(
        ["powershell", "-NoProfile", "-Command", cmd],
        capture_output=True, text=True, timeout=15
    )
    return r.stdout.strip()

def verify(target_domain: str, target_ips: list[str]) -> dict:
    report = {
        "timestamp": datetime.now().isoformat(),
        "checks": {},
        "routes": [],
        "passed": False,
    }

    # 1. 专网
    out = _ps(f'(Test-NetConnection {target_domain} -Port 443).TcpTestSucceeded')
    report["checks"]["intranet_443"] = (out.lower() == "true")

    # 2. 外网
    out = _ps('Test-NetConnection 8.8.8.8 -InformationLevel Quiet')
    report["checks"]["internet"] = (out.lower() == "true")

    # 3. 路由摘要
    out = _ps(
        'Get-NetRoute | Where-Object {$_.DestinationPrefix -ne "ff00::/8"} '
        '| Select-Object DestinationPrefix,NextHop,InterfaceAlias,RouteMetric '
        '| ConvertTo-Json -Compress'
    )
    try:
        report["routes"] = json.loads(out) if out else []
    except json.JSONDecodeError:
        report["routes"] = []

    # 4. 专网 IP 路由是否存在
    prefixes = {r.get("DestinationPrefix") for r in report["routes"] if isinstance(r, dict)}
    report["checks"]["target_routes"] = all(f"{ip}/32" in prefixes for ip in target_ips)

    report["passed"] = all(report["checks"].values())
    logger.info(f"验证结果：{report['checks']}  passed={report['passed']}")
    return report
```

#### 3.6.3 成功 / 失败判定

- **成功**：`intranet_443 == True` 且 `internet == True` 且 `target_routes == True`
- **失败**：任一为 False，进入告警流程，并保留报告 JSON 用于排障

## 5. 异常处理与告警

| 异常场景 | 处理策略 | 重试次数 | 告警方式 |
| --- | --- | --- | --- |
| WiFi 连接超时（>30s） | 等待延长 1 倍后再试，仍失败则放弃本轮 | 2 | loguru WARNING + 主程序事件总线 |
| DNS 解析失败 | 退化到历史缓存 IP；缓存也无 → 终止配置 | 3（指数退避 2/4/8s） | ERROR + 邮件/钉钉 |
| 路由配置失败（权限不足） | 检测 `IsUserAnAdmin`，独立 exe 自动 UAC 提权；服务模式直接告警 | 1 | ERROR + 主程序弹窗 |
| 路由配置失败（命令报错） | 解析 PowerShell stderr，常见冲突路由自动 `Remove` 后重试 | 2 | WARNING |
| 验证失败：专网不通 | 检查路由是否真写入 → 检查 WiFi 是否拿到 IP → 重新执行 Step 3~5（诊断→解析→配置） | 2 | ERROR + 报告留存 |
| 验证失败：外网不通 | 提示运维检查有线网卡；不自动改写外网路由 | 0 | WARNING |
| U-Key 拔出后立即重新插入 | 防抖：拔出后 3 秒内插入按"网络抖动"处理，不重复完整流程；超过 3 秒走完整 setup | - | INFO |
| WMI 查询异常（杀毒拦截） | 退化到 `Get-PnpDevice` PowerShell 兜底 | 持续 | WARNING（首次） |

告警通道由主程序统一封装，本模块只发事件不直接对接外部。

## 8. 部署注意事项

### 8.1 权限

- **必须以管理员身份运行**：`Remove-NetRoute` / `New-NetRoute` 强制要求 Administrator
- 独立 exe：PyInstaller 打包时使用 `--uac-admin`，启动时自动弹 UAC
- 服务模式：建议主程序入口 `main.py` 顶部调用 `route_writer.ensure_admin()`，否则启动即提示

### 8.2 防火墙与杀毒

| 软件 | 影响 | 处理 |
| --- | --- | --- |
| Windows Defender 防火墙 | 不会阻止路由配置 | 无需处理 |
| 360 / 火绒 / 卡巴斯基 | 可能拦截 WMI / PowerShell 调用 | 安装时引导加入信任区；提供数字签名 exe |
| 企业版终端管控 | 部分 EDR 会阻止 `Remove-NetRoute` | 提前与客户 IT 沟通加白 |

### 8.3 网卡命名兼容

WiFi 网卡名因系统语言/版本不同，常见值：

- 英文：`Wi-Fi`、`WLAN`
- 中文：`无线网络`、`WLAN`、`无线网络连接`

**自动检测策略**：

```python
import subprocess, json
def auto_detect_wifi_interface() -> str:
    out = subprocess.run(
        ["powershell", "-NoProfile", "-Command",
         "Get-NetAdapter | Where-Object {$_.PhysicalMediaType -eq 'Native 802.11'} "
         "| Select-Object -First 1 -ExpandProperty Name"],
        capture_output=True, text=True
    ).stdout.strip()
    return out or "Wi-Fi"
```

### 8.4 多 USB WiFi 共存

某些场景下用户已使用 USB WiFi 接外网，再插 U-Key 接专网。此时：

- `wan_interface` 配为外网 USB WiFi 的网卡名
- VID/PID 必须**显式指定**，不可使用 `auto`

### 8.5 持久化策略

- 默认使用 `-PolicyStore ActiveStore`，重启不保留
- 服务模式下重启后由 `route_manager` 重新触发完整流程，**无需** PersistentStore
- 独立 exe `setup` 子命令可加 `--persistent` 选项写入 `PersistentStore`（仅推荐固定 IP 场景）

### 8.6 卸载

```bash
net_config_tool.exe reset
# 等价于：删除所有目标 /32 路由 + 清空 cached_ips
```
