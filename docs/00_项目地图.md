# spider-gd 项目地图

> 最后更新：2026-06-23 | 测试基线：155 passed / 1 skipped | ruff ✅ | mypy 0 error

## 快速导航

### A 接入认证层 ✅

- `core/crawler/login_flow.py` — 登录编排：账密+验证码+提交+校验，产出 Session
- `core/crawler/captcha_solver.py` — 验证码识别（ddddocr，字母+数字，延迟加载）
- `core/crawler/session_keeper.py` — 会话守护：412→refresh→完整重登→终止，防重入锁
- `core/crawler/session_provider.py` — 凭证提取：从 Playwright 页面读 Token/HdKGccbL/Cookie
- `core/crawler/playwright_runner.py` — Playwright 浏览器适配器（延迟导入，运行时依赖）
- `core/crawler/ukey_manager.py` — U-Key 插入自登录+有效期记录+续期/过期告警
- `core/crawler/task_lock.py` — 跨进程文件锁（O_EXCL 原子创建+6h 过期回收）

### B 调度策略层 ✅

- `core/scheduler/task_scheduler.py` — APScheduler 封装：cron 定时+手动立即触发
- `core/scheduler/retry_policy.py` — 指数退避重试策略（异步）
- `core/scheduler/backfill.py` — 自动补漏规划（防雪崩三限制：单次限额+冷却+低优先级）

### C 采集引擎层 ✅

- `core/crawler/crawl_orchestrator.py` — 状态机编排器（task_items 粒度断点续采+部分失败聚合）
- `core/crawler/api_fetcher.py` — 通用 API 采集引擎（配置驱动，412→TokenExpiredError）
- `core/crawler/rpa_fetcher.py` — RPA 兜底引擎（API 失败→浏览器仿真导出）
- `core/crawler/exceptions.py` — 爬虫核心异常定义（CrawlerError 层级）

### D 数据处理层 🟡（标准化待阶段 2.5）

- `core/pipeline/data_processor.py` — Excel 解析+校验+原始 DataFrame 落地（字段标准化推迟）
- `core/pipeline/local_landing.py` — 本地文件落地：分层目录+台账 Excel（红绿状态）+zip 压缩

### E 存储层 ✅

- `infrastructure/storage/database.py` — SQLite 任务状态追踪（WAL 模式，线程安全）
- `infrastructure/storage/retention.py` — 保留期自动清理（按日期目录+空月清除）

### F 远程控制层 🟡（Stream/审计待阶段 3）

- `gateway/api/server.py` — FastAPI REST（4 端点）+暗色 Web 仪表盘
- `gateway/control_service.py` — REST+Agent 共用统一控制服务（DRY）
- `gateway/agent/agent_adapter.py` — Agent 适配层：接收指令→解析执行→返回结果
- `gateway/agent/command_executor.py` — 指令解析与执行：自然语言→操作+权限校验
- `gateway/agent/handlers.py` — 3 个真实 Agent handler（trigger_crawl/health_check/query_result）
- `gateway/agent/permission_guard.py` — 三级权限控制：readonly < config < system
- `gateway/agent/stream_client.py` — Webhook 回传完整+Stream 占位（需企业应用 AppKey）

### G Web UI 层 🟡（骨架完整，增强待做）

- `gateway/api/server.py` — 暗色控制台（健康/任务/手动触发），web_ui 开关驱动

### H 网络配置层 ✅

- `infrastructure/network/usb_monitor.py` — U-Key USB 设备插拔监控（WMI 轮询+VID:PID 匹配）
- `infrastructure/network/dns_resolver.py` — 专网域名解析三级回退：WiFi DNS→ping→历史缓存
- `infrastructure/network/network_validator.py` — 双网络连通性验证（专网+公网+路由正确）
- `infrastructure/network/route_writer.py` — 路由表配置（PowerShell 封装+管理员权限检查）
- `infrastructure/network/supervisor.py` — 双网卡持续监控+专网自动重连+公网失败降级模式 D
- `infrastructure/network/diagnoser.py` — 网络诊断：插拔前后路由/适配器/DNS 快照对比推断根因
- `infrastructure/network/_powershell.py` — PowerShell 子进程调用统一封装（单一 Mock 点）

### I 部署运维层 ✅

- `app.py` — 依赖注入装配入口（按 ModuleToggle 条件装配，业务模块无 if mode）
- `__main__.py` — CLI 统一入口（argparse 子命令路由）
- `config/deploy_mode.py` — 部署模式枚举与 ModuleToggle 模块开关
- `config/settings.py` — 配置加载：pydantic-settings+多 YAML 继承+.env
- `config/logging.py` — 全局 loguru 配置：滚动日志+按任务独立 sink+脱敏

## 关键设计决策

- **编排器是状态机而非线性管道** — task_items 粒度断点续采，item 独立 pending→success/failed → 见 `docs/05_模块化架构设计.md`
- **session_keeper 独立封装** — 412 重登逻辑单一职责，不硬编码进编排器 try/except
- **DataProcessor 范围切分** — 标准化推迟到拿真实样本后（阶段 2.5），避免基于 mock 写出会被推翻的逻辑
- **配置热更新为非目标** — 改配置后重启即可，降低运行时复杂度 → 见 `docs/` 相关讨论
- **模式 C 双机已废弃** — 单机双网卡足够，assemble 按 ModuleToggle 条件装配
- **业务模块不写 if mode** — deploy_mode.py 定义开关，app.py 统一装配，业务层零感知
- **SQLite 仅存状态不存业务数据** — 任务状态追踪用 WAL 模式，实际数据走文件落地
- **接口优先 RPA 兜底** — ApiFetcher 失败时回退 RpaFetcher，两引擎共享 SessionKeeper
