# 采集端产品体验重设计

这一步只做产品设计，不改业务代码。分支从 `dev` 的 `1d4aabf` 切出，目标是让普通用户从界面本身看懂「采什么、什么时候采、存到哪」，而不是先读一段说明。

视觉仍走国央企风格：稳重、对齐、配色克制。不引入营销感插画，不把主色改成亮绿或亮蓝。

## 怎么看现状

桌面端是 Electron 渲染层，页面数据来自本机 `http://localhost:8800`，还依赖 `window.api`。这台环境没有可用的后端和预加载脚本，前端起不来，所以没有真实运行截图。

现状图按源码还原：导航、按钮文案、卡片字段和说明原文都来自现有页面。改版图是静态 HTML 原型，用系统 Chrome 无头模式截成约 1280 宽的 PNG。两套图都标了「现状还原」或「改版示意」，避免把示意图当成线上界面。

## 信息架构

现在左侧五个入口是「任务配置、文件中心、执行日志、指标配置、录制工坊」。设置不在导航里，是顶栏弹窗。新建任务和补数据共用三步：「基本信息、采集范围、存储结构」。步骤名描述的是表单分区，不是用户要做的事。日期用 `D-1`、`M-1`、`W` 表示，存储用「自定义结构（YAML）」或 `{YYYY-MM}/{YYYY-MM-DD}` 表示。

建议把日常使用收成一条任务：

1. **采什么**：选指标，用业务名，不展示工作流文件名。
2. **什么时候**：用「昨天 / 今天 / 最近 7 天」这种结果，旁边写出若按当前计划运行会落到哪一天。
3. **存到哪**：直接展示文件夹路径和一份示例文件名。

导航改成四个日常入口：任务、文件、记录、指标。录制工坊和 YAML 编辑收进指标页的「维护」里，普通值守不看见。设置仍从顶栏进入，但分组去掉表情符号，只留「本机、登录、存放、关于」。

高级项默认收起：重试次数、上传配置、自定义文件名、按导出单独选日期。需要时再展开，展开后用一句结果说明，不再用一段规则。

## 页面盘点

### 任务列表（首页）

路由 `/`，导航名「任务配置」。用户要在这里确认今天会不会采、采的是什么、出了问题去哪看。

现在卡片上写的是：

- 调度：`每天 08:00`
- 日期：`现货交易-完整采集（含披露中心）：D-1 ~ D-1`
- 存储：`自定义结构（YAML）` 或 `{YYYY-MM}/{YYYY-MM-DD}`
- 下次执行：`2026-11-14 08:00` 或 `已禁用`

搜索框占位是「搜索任务名称、指标或备注」。空状态是「暂无自动化任务，点击右上角"新增任务"开始」。顶栏同时放「导入、导出全部、补数据、新增任务」。

看不懂的地方：`D-1` 要先记住 D 是运行日；「自定义结构（YAML）」看不出文件会落在哪个文件夹；四个顶栏按钮权重一样，补数据和新建混在一起。状态只有「已启用 / 已禁用」，看不到上次是成功还是失败。

改版：卡片直接写「每次采集昨天」「下载目录 / 现货 / 2026-11 / 13」。主按钮只留「新建采集」，补采降成次按钮。卡片右上角用状态色写「每天 08:00 运行」或「已停用」，底部写上次结果。空状态改成「还没有采集任务」加一个「新建采集」按钮，不再指示用户去找右上角。

### 新建 / 编辑任务

弹窗三步，定义在 `TASK_EDITOR_STEPS`：基本信息、采集范围、存储结构。

第一步字段：名称占位「例如：现货出清电量采集」；登录方式提示「选择用于登录的工作流」；指标占位「选择采集指标」；时间占位「选择时间」；备注占位「可选：补充说明」。重试次数的提示是一整段：

> 下载超时、元素等待超时、业务页丢失、导航失败时，先回到工作台再试。默认 3 次。登录失败、证书错误和第二次 HTTP 400 会停止整个任务。

第二步顶部说明：

> D = 运行当天，M = 运行当月。修改仅影响当前任务，不会更改指标配置；补数据时选择的日期会覆盖任务范围。

滑块下还有：

- 「昨天。D 是运行当天。」
- 「上月。M 是运行当天所在的月份，每个月查一次整月。」
- 「……W 是运行当天所在的周，每周采集一次。」

未选指标时：「先在「基本信息」里选择采集指标，再设置各自的时间范围。」

用户在这里要完成的事其实就是三件：选数据、定节奏、定落盘位置。现在第二步把「不会改指标配置」「补数据会覆盖」和 D/M 定义绑在同一句里，三件互不相关的话要一起读完才能拖滑块。

改版：步骤改名为「1 采什么 / 2 什么时候 / 3 存到哪」。日期改成可点的结果：「昨天」「今天」「最近 7 天」，旁边写「若今天 08:00 运行，将采集 2026-11-13」。D/M/W 滑块收进「自定义」。重试收成「高级：失败后再试 3 次」，点开后再写「登录失败和证书错误不会重试」。那句「不会更改指标配置」删掉，因为普通用户没有这个担心。

### 补数据

标题「补数据」，和新建任务共用三步。开头：

> 仅执行一次，不会修改定时任务。接下来再选补数时间和下载路径。

第二步：

> 时间留空时使用该指标的默认采集范围，具体日期见下方预览。这一步不会改任务卡片上的区间。

占位分别是「留空使用默认日期 / 默认月份 / 默认周」「选择这个导出要补的日期」「选择要补的指标」「选择登录工作流」。预览里会出现「默认 D-1」。按月还有一句「按月指标会查询所选月份的整月数据。」存储步提示：

- 「已按上面的路径执行这一次，不会写回定时任务。」
- 「默认沿用任务「…」的下载路径和存储结构，只影响这次补数。」
- 「没有匹配到任务的存储配置，文件放在这个下载路径下。只影响这次补数。」

用户要做的是：选哪几项、补哪几天、确认文件放到哪，然后跑一次。现在「不会修改定时任务」说了三次，默认日期仍写成 `D-1`，还要再走一遍和定时任务一样的三步。

改版：标题改成「补采一次」，副标题只留「不改变每天 08:00 的定时任务」。一屏完成：要点选的数据、要补的日期、存放路径、将生成的文件数和一条示例文件名。存放位置默认沿用任务，改路径收进「改这次的存放位置」。

### 存储结构与自定义文件名

嵌在任务第三步和补数据第三步。可见说明包括：

> 工作流 save_as 里写了目录（运行时已忽略），已按它回显成文件夹结构。保存后由这里控制落盘，再把工作流里的 save_as 改成纯文件名。

> 点击放进「…」，或拖到任意文件夹

空目录：「拖文件或标签到这里」「从左边把 WiFi、日期、文件夹或文件拖进来，或点上面的「新建文件夹」」。失效、重名、未写 `save_as` 时各有一条提到 YAML / `name` / `save_as` 的警告。

自定义文件名弹窗：

> 仅对当前任务生效。只填文件名，扩展名仍用原文件的 .xlsx。重名时直接覆盖旧文件。

下面再列 `{yyyy}` `{MM}` `{dd}` `{yyyyMM}` `{yyyyMMdd}` `{yyyy-MM}` `{yyyy-MM-dd}`，并给示例「现货分时分类型出清电量-日前-20261112.xlsx」。

普通用户只需要看到最终路径。`save_as`、YAML、标签拖拽是维护人员的工具。建议默认展示一条路径加示例文件名；「调整文件夹」再打开现在这套结构编辑器。自定义命名默认关，打开后输入框右侧实时出预览，变量表收进输入框下方的一行短提示，点变量即可插入，不再先读完整段变量说明。失效和重名警告留着，但改成「这两个文件会互相覆盖」这种结果句，YAML 建议放到「查看原因」。

### 执行日志

路由 `/execution-logs`。筛选项是「指标播放、定时自动、定时手动、补数据、数据上传」和「执行中、已暂停、成功、失败」。时间范围占位「开始时间 / 结束时间」。页面本身说明不多，问题是类型名偏内部：用户分不清「指标播放」和「定时手动」。

建议类型改成「手动试跑、定时、补采、上传」。状态色沿用成功绿、暂停琥珀、失败红。点一行展开本次采了哪些文件、停在哪一句，不再要求用户另开日志目录才能看懂。

### 文件中心

路由 `/files`。空目录是「该目录为空」，版本空态是「暂无历史版本。」右键有「打开文件夹、在文件管理器中定位、重命名、压缩为 ZIP、发布到云端、版本信息、删除」。

用户来这里是找某天的文件。建议顶部按任务和日期筛选，空目录写成「这一天还没有文件」，并给出「去补采」而不是只说目录为空。「发布到云端」对未配置上传的环境收起。

### 指标配置

路由 `/indicators`。左侧是工作流树，右侧可在「步骤」和「YAML」之间切换。空步骤写「暂无步骤，请切换到 YAML 编辑」。导入按钮是「导入 YAML」「导入 ZIP」。登录流程描述是「登录流程：从主界面 → 证书登录 → 工作台」。日期配置弹窗写着「指定的范围写在 YAML 对应导出步骤的 start / end 上……」，重名提示是「同一指标里有重名导出，在 YAML 的这一步补上 name 才能稳定区分」，读失败是「读不出日期配置，先检查 YAML 语法」。

这是维护页，YAML 可以留下，但不要作为默认视图。默认用步骤卡片：点哪、填什么、导出成什么文件。YAML、导入、重名修复收进「维护」。

### 录制工坊

路由 `/record-workshop`。标题带表情「📹 录制工坊」。帮助弹窗「交互式工作流构建」正文是：

> 点击「开始构建」后浏览器会打开设置中的网站地址，右侧出现步骤面板。

> C 点击 · H 悬停 · D 日期 · S 下拉 · F 填入 · E 导出 · X 提取 · W 等待

> 录完后在浏览器面板点「完成」，ZIP 会保存到下载路径下的「录制工坊」文件夹，并自动关闭浏览器。

> 历史记录中可点击「提交」标记为已提交；远程上传地址可在设置中配置（暂未对接）。

快捷键不能靠界面猜出来，这段说明应留下，但改成开始录制后贴在步骤面板底部的一行，而不是先打开一个帮助弹窗。未对接的「远程上传」从帮助里删掉，避免用户以为已经能提交到远端。

### 设置

从顶栏打开，分组是「📦 基础、☁️ 数据上传、🌐 网站信息、ℹ️ 关于」。证书相关有一段操作说明：

> 配了两个及以上场站时，点立即执行会先弹出多选窗口。证书窗口的列是颁发给、单位、截止日期、颁发者，用来对上的是「单位」。单位名称写一段能对上的字即可，例如单位是「三峡新能源阳江发电有限公司」时写「阳江」……改完要点右下角「保存」。

上传里还有「本机微信 PoC 只适合 Windows 值守机：需要微信已登录、桌面未锁屏……」。

建议分组改成「本机、登录与场站、通知、关于」，去掉表情。证书对照规则留在场站行的「怎么填单位」气泡里，用用户自己的单位名做例子，不要放在分组说明里。微信实验项默认折叠，标题改为「本机微信（实验）」，限制条件留在展开后的第一行。

### 执行中的弹窗

进度和结果弹窗、浏览器会话面板文案相对短，问题主要是失败原因仍带内部词，例如「业务页面加载失败（chrome-error），请在专用浏览器中刷新并确认 U-Key 证书客户端已运行后重新登录」。建议主句改成「页面没打开。请确认证书客户端已运行，然后在采集浏览器里刷新。」技术词放到「详情」。

## 说明文字怎么处理

| 处理 | 内容 |
| --- | --- |
| 删除 | 「不会更改指标配置」「这一步不会改任务卡片上的区间」「接下来再选补数时间和下载路径」；D/M/W 的定义句；卡片上的「自定义结构（YAML）」；设置分组上的表情；录制帮助里「暂未对接」。 |
| 改成界面本身 | 日期改成「昨天」并写出具体日期；存储改成路径；步骤名改成采什么 / 什么时候 / 存到哪；空状态带一个主动作。 |
| 收成短提示或气泡 | 重试何时停止；自定义文件名的变量；证书单位怎么对；录制快捷键；同名覆盖。 |
| 留下 | 真正的失败原因、覆盖警告、证书和微信的使用限制、录制快捷键。这些不是用法说明书，是不看就会误操作或误判的事实。 |

「仅执行一次，不会修改定时任务」只保留一次，放在补采标题右侧，不再在每个步骤重复。

## 视觉规范

克制、对齐、少色。主色用深蓝，不用现在启动绿 `#10B981` 和 Ant 默认蓝 `#1677ff` 做主按钮。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 主色 | `#0E3A5D` | 顶栏、主按钮、当前步骤 |
| 主色悬停 | `#1A5080` | 侧栏选中、主按钮悬停 |
| 点缀 | `#8C7340` | 仅用于示意图角标或极少量强调，不用于按钮 |
| 页面底 | `#F3F5F7` | 主背景 |
| 卡片 | `#FFFFFF`，边框 `#E3E6EA` | 列表和弹窗内容 |
| 正文 | `#1C2430` | 标题和正文 |
| 次文 | `#5E6976` | 标签、辅助说明 |
| 成功 | `#1F7A4D` | 运行中、上次成功 |
| 警告 | `#8A5A00` | 暂停、待处理 |
| 危险 | `#9B2C2C` | 失败、覆盖风险 |

字号：页面标题 20 / 600，卡片标题 16 / 600，正文 13，辅助 12。行高 1.5。圆角 4，卡片 6。间距用 8 的倍数：卡片内边距 16，卡片间距 16，页面边距 28。

按钮只分两级。主按钮实心深蓝，一屏一个。次按钮白底灰边。危险操作用文字按钮或次按钮加确认，不用大面积红色。状态用字色加文字，不只用颜色，例如「每天 08:00 运行」「已停用」「上次失败」。

侧栏保持窄轨、图标加两字。选中用主色块，不使用渐变。

## 三张关键页

### 任务列表

现状把日期和存储写成规则。改版后每张卡片回答四个问题：采什么、每次采哪一天、文件在哪、下次何时跑。上次成败写在卡片底部，失败的任务不用点进日志才知道。

### 任务配置第二步

现状要先读 D/M 定义再拖滑块。改版用选项表达结果，并把「如果就按现在的计划跑，会采到哪一天」写在选项上方。自定义范围和重试次数都收起来。

### 补采

现状用三步表单，并反复说明不会改定时任务。改版合成一屏：选数据、选日期、看路径、看将生成的文件，然后「开始补采」。示例文件名使用 `现货分时分类型出清电量-日前-20261112.xlsx`，和现有命名规则一致。
