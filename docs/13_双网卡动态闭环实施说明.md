# 双网卡动态闭环实施说明

## 背景

客户现场的专网入口依赖 U-Key/随身 WiFi。该网络下 `pm.gd.csg.cn` 对应的 IP 可能随拔插、DHCP、专网侧调整而变化，因此不能把专网 IP 写死在配置里。

目标闭环：

1. 插上 U-Key。
2. 连接指定的 U-Key/WiFi 网卡。
3. 通过该网卡分配的 DNS 解析专网域名。
4. 删除该 WiFi 默认路由，避免抢占公网。
5. 清理上一次缓存 IP 对应的旧 `/32` 路由。
6. 为当前解析出的专网 IP 写入 `/32` 精确路由。
7. 验证专网可达。
8. 检查公网是否可达；公网不可达只标记降级，不阻止本地采集。

## 当前实现

核心入口：`DualNicClosure`

路径：`src/spider_gd/infrastructure/network/dual_nic_closure.py`

调用链：

- `DnsResolver`：读取指定网卡的 DNS 服务器，并通过该 DNS 解析专网域名。
- `RouteWriter`：删除 WiFi 默认路由，清理旧 `/32`，写入新 `/32`。
- `NetworkValidator`：用解析出的 IP 验证专网 443，并检查 `/32` 路由是否落在指定网卡；随后验证公网 HTTPS。
- `WifiConnector`：可选的任务前 WiFi 准备，按设置连接目标 SSID，然后再进入双网卡闭环。
- `/api/network/route-rules/apply`：前端“保存并应用”按钮和顶部“专网”状态点击都会先做 WiFi 准备，再触发该闭环。
- 定时/手动任务预检：启动 `TaskRunner` 前会先运行 WiFi 准备和双网卡闭环；失败时直接写执行日志、发送告警，并停止本次采集。

## 配置方式

在设置页的“路由”区域配置：

- 任务前连接指定 WiFi：可选开启，先选择 WiFi 网卡，再从扫描列表选择目标 WiFi；扫描不到隐藏 SSID 时可手动输入。
- WiFi 密码：首次配置或更换密码时填写；留空会保持已保存密码，也会尝试使用系统已保存 WiFi 配置。
- 连接失败中止任务：开启后，自动连接失败会让本次任务直接失败并告警；关闭后只记录警告并继续后续预检。
- 域名：`pm.gd.csg.cn`
- 网卡：选择 U-Key/随身 WiFi 对应的网卡名称
- SSID：可选，填写后会校验该网卡当前连接的 WiFi 是否就是指定 SSID

点击“刷新”会扫描当前网卡附近的 WiFi 列表；点击“测试连接”会只验证 WiFi 准备；点击“保存并应用”后，后端会先连接 WiFi，再重新解析域名，不依赖上一次固定 IP。

## 运行结果

API 返回：

- `status=ok`：解析、路由写入、专网验证、公网验证全部通过。
- `status=degraded`：专网和路由通过，公网不可达；允许采集继续落本地。
- `status=error`：专网解析、路由写入或专网验证失败。
- `resolved_ips`：本次通过专网 DNS 得到的 IP。
- `stale_ips`：上次缓存的 IP，会被用于清理旧路由。
- `private_ok`：专网 443 是否可达。
- `public_ok`：公网 HTTPS 是否可达。
- `routes_ok`：`/32` 路由是否存在，并且是否挂在指定网卡上。
- `expected_ssid/current_ssid`：配置了期望 SSID 时，用于判断是否连错 WiFi。

前端在 `status=ok` 时提示双网卡验证通过；在 `status=degraded` 时提示专网可用、公网不可达，采集仍可继续落本地；只写入路由但专网验证失败不会被当成成功。

定时和手动任务只要求网络准备和专网闭环通过后才进入浏览器采集；如果 U-Key 未插、WiFi 未连、专网 DNS 解析失败、路由写入失败或专网不可达，本次任务会以失败结束并触发错误告警。公网断开时任务继续执行，数据先落本地，后续等待恢复网络或人工上传。

## 现场排障顺序

1. 网卡列表中是否能看到 U-Key/WiFi 网卡。
2. “测试连接”是否能自动连接到指定 WiFi；如果密码留空，系统里是否已有该 WiFi 配置。
3. 如果配置了 SSID，`current_ssid` 是否等于 `expected_ssid`。
4. `Get-DnsClientServerAddress` 是否能看到该网卡分配的 DNS。
5. 专网 DNS 是否能解析 `pm.gd.csg.cn`。
6. 是否以管理员权限运行程序。
7. `/32` 路由是否落在 U-Key/WiFi 网卡，而不是公网网卡。
8. 删除 WiFi 默认路由后，公网 HTTPS 是否仍然可达。
